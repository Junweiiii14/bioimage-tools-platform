## 4. 唯一推荐方案：图像为中心的自动化工作台

主线：**工具平台 → 选择 WB 原图 → 自动建立项目并处理 → 只处理需要关注的项 → 查看拼图和结果 → 导出结果包。**

保留当前原生 Qt 技术栈，通过组件、字体、留白、状态和布局做到网页般细腻。此次方案不包含技术栈迁移，也不扩展其他实验工具。

### 4.1 平台首页

- 左侧紧凑工具导航，明确“工具平台 / WB 自动化”，以后工具可复用同一入口逻辑，但本轮只实现 WB。
- 主区展示 WB 的一句用途说明和唯一主按钮“选择 WB 原图并开始”。支持文件多选；整目录导入与拖放作为同一入口的补充。
- 下方为最近项目：可识别名称、图片缩略图、最近时间、“处理中 / 待复核 / 可导出”等真实状态。点击继续。
- “打开已有项目”“恢复项目包”是次级操作；帮助按需打开，不常驻占一整栏。

### 4.2 自动建项目规则

1. 用户选图或原图文件夹；先扫描可支持文件。取消选择或没有可支持文件，不留下空项目。
2. 软件在用户文档目录下的 `BioImage/Projects/` 自动创建唯一子文件夹。项目显示名初始取来源文件夹名和日期，可稍后改；目录加入短唯一标识防重名。此为拟定默认位置，跟随系统实际文档路径。
3. 原图文件夹只作为输入，不要求为空，也不作为项目保存目录；原始文件和历史结果不可覆盖。若选择上层目录，应排除应用自身项目/输出，避免递归重新导入产物。
4. 正常情况无额外建项目弹窗，直接进入自动处理。保存位置在设置或项目详情中可改；权限/空间失败时显示具体原因和“换保存位置”，不要求用户先手动建空目录。
5. 再次导入同一批图，从平台开始则创建新项目；在已有项目内使用明确“添加原图”。打开已有项目是单独行为，不能混入新建。
6. 扫描→导入→识别泳道与裁剪→测量→生成拼图和结果草稿自动串联，展示当前阶段、进度、已完成/失败数。部分坏图继续，失败可定位；取消保留已经完整提交的结果，未完成项明确标记。
7. 首次至少一个文件读入成功后建立可继续项目；全体解码失败则显示文件失败列表，清理由本次创建且确认未承载有效数据的临时资源。不得删除任何用户目录或历史内容。

### 4.3 WB 固定三栏

```text
工具平台 / WB    项目名称 · 已保存/处理中                 [添加原图] [导出结果]
                图像复核          拼图          结果
┌────────────────┬───────────────────────────────┬────────────────────┐
│ 原图与任务      │ 当前原图 / 当前拼图 / 结果预览 │ 当前选中对象        │
│ 全部 | 需关注   │                               │ 识别摘要与异常原因  │
│ 缩略图+文件名   │    图像为主，可缩放和拖动     │ 对应的图上调整工具  │
│ 处理/复核状态   │    裁剪框、泳道叠层           │ 确认与下一个待处理  │
│ 点击定位问题    │    按需展开所选泳道曲线       │ 高级设置（收起）    │
└────────────────┴───────────────────────────────┴────────────────────┘
```

- 1440 宽参考：左 224、右 280，中间自适应；顶部约 56，视图切换约 40。1100 宽缩减侧栏/允许收起，保证中央图像可用。数字是设计目标，需高 DPI 实测后调整。
- 左侧“需关注”聚合未检出、读取失败、测量质量、待确认，并保留不同原因，不能一律标红或一律叫失败。
- 右侧只呈现当前选中图/泳道的内容。比如“未找到可靠泳道 → 在图上框选膜区域后重新识别”；“测量质量警告 → 查看具体原因与曲线”。正常项不会被迫填写高级参数。
- 裁剪框和泳道可在图上调整；曲线积分边界/基线拟增加拖动手柄和键盘微调。**当前只确认已有裁剪图上调整，曲线调整是待实现能力。**
- 改动自动保存并使相关旧结果失效，后台重算受影响项；旧任务不能覆盖新编辑。提供撤销/重做与恢复机器建议；最终有效值必须来自当前版本完整结果。
- “确认裁剪”仅确认几何范围，不能清除测量质量警告或自动变成有效定量。显示亮度调整不能解决原像素质量问题。

### 4.4 OCR、实验信息与归一化

这些能力继续完整保留在本轮产品中，不因简化默认界面而删掉或延期。

- 拼图 Fig/行名 OCR 与写表从“拼图/结果”上下文进入：有待识别拼图时提供识别并填表，展示候选文本和来源，必要时校正与确认绑定。由软件生成且来源明确的标签可直接传递，不重复要求输入；外来标签不能猜配到原图。
- 批量信息采用“选择来源方式 → 映射预览 → 应用”，自动处理主线不要求先打开七组参数。
- 归一化采用“目标与参照 → 样本对应 → 计算结果”。已有明确且核验有效的关系可复用，无关系时说明缺项并定位，不推断蛋白、内参、对照或分母。
- 这些任务面板按上下文打开，保持中央图像/结果位置稳定，避免再建立全屏复杂标签页树。

### 4.5 拼图与导出

- 自动处理后生成当前可用拼图草稿；已有完成拼图重开可查看，失效内容明确标记并更新，不让用户例行点击“重建/刷新”才能看到作品。
- 拼图视图：左侧来源与模板，中央大预览，右侧选中元素的标题/间距/排列等属性。模板保存/导入保留，字体管理与完整段表进高级入口。
- 结果视图集中展示数值、来源、状态及原因；一个主动作“导出结果包”。默认组合拟包含 XLSX、PNG、显示 TIFF、可恢复 ZIP 与状态说明；CSV 和单项格式在次级选择中。
- 导出前显示实际可用内容、待复核/失败数及保存位置；完成后显示实际文件和“打开结果文件夹”。每次输出新版本，不覆盖既有结果。
- 待复核内容可以形成明确标注状态的草稿包，不冒充已完成实验结果；缺失或无效值保持空值与原因。原值资产保留在可恢复项目中，显示图不进入定量。

### 4.6 视觉规格

方向为安静、清晰的科学工作台。Taste 的 putty/black 方向用于低饱和暖灰外壳和深色文字；图像画布使用中性背景，避免彩色底干扰观察。

| 元素 | 拟定规范 |
|---|---|
| 外壳/面板 | 近白与浅暖灰，小面积层级变化；画布使用中性灰 |
| 文字 | 深石墨主文字，次要文字降低权重但维持可读性；Segoe UI / Microsoft YaHei UI，中文适配 |
| 强调 | 单一低饱和蓝青 `#256f82` 用于主要动作和选中；警告琥珀、失败红、确认绿，同时带文字/图标 |
| 字号 | 正文 13–14、分区 16–18、项目标题约 20；不使用营销页大标题 |
| 密度 | 基于 8 的间距；普通控件高约 32–36；只给真正的控件/分区边界，不给每块内容套卡片 |
| 状态 | 主操作每个上下文一个；保存/处理中/需复核/已导出区分；提示与当前页面一致 |
| 动效 | 仅短反馈、面板展开和进度；关闭装饰性持续动效，避免阻碍图像操作 |

所有尺寸/对比度在真实原生控件、长中文文件名和 DPI 条件下验证后确定，不把此表当成已落地 token。

## 5. 审核通过后的实施安排

1. 项目创建与状态链：自动管理目录、文件选择/扫描/错误恢复、处理进度与结果版本。
2. 主工作台：平台入口、紧凑顶部、三栏、图上调整、异常队列、保存/撤销与过期结果防护。
3. 拼图与完整输出：模板、OCR/写表、批量信息、归一化上下文入口和统一结果包，不删减已有业务能力。
4. 集成验收：真实 WB 资料跑全流程；独立代码与交互审查；窄窗口、高 DPI 和恢复场景。只在真实通过后展示运行效果。

## 6. 可检验的验收条件
