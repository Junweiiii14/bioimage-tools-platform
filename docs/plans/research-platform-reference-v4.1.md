## 1. 要做出什么软件

做一个供实验室使用的、可以编排分析操作的软件。它像一套可视化宏：把实验人员在不同软件中反复执行的操作，做成可以连接的模块；用户选好流程、设置参数、导入一批数据，就能自动得到结果。

用户可以直接用现成实验模板，也可以替换其中某一步、调整参数，再保存为本实验室的模板。界面提供模块列表、流程画布、参数面板和结果预览。每一步能看到输入、输出和实际使用的设置，同一流程可以批量运行。

例如，一条待调研的WB流程可能是“导入原图 → 确定分析区域 → 背景处理 → 条带测量 → 归一化 → 输出表格和图片”。这只是说明产品形态，不代表所有实验室都应采用同一种测量方法。

开发重点是：**先弄清楚实验人员怎样完成分析，再把已验证的操作做成可复用模块。** Agent不是前置条件，以后可以辅助寻找模块和配置流程。

## 2. 怎样调研真实分析流程

每次选择一个明确场景，例如“某实验室某类WB图像的定量”，不要直接研究笼统的“所有WB分析”。先找齐能互相对照的材料：原始数据、现行操作说明、软件及版本、关键中间文件、最终结果。使用已有授权材料；没有材料时记录缺口，可以做工程原型，但不能宣称已覆盖真实流程。

让熟悉该流程的人用代表性数据演示完整过程，记录在哪里点了什么、填写什么参数、为什么这样选择。尤其要记录容易忽略的动作：先裁哪块区域、何时改阈值、为什么排除这个对象、怎样对应样本组、如何转到另一款软件。不能只记最后点击的“分析”按钮。

整理成一张操作清单：

| 要记录什么 | 具体内容 |
|---|---|
| 操作目的 | 输入什么，想得到什么结果 |
| 原软件操作 | 软件、版本、插件、功能名称、菜单位置或命令、操作顺序 |
| 实际设置 | 参数、单位、默认值、区域选择；哪些每批要改 |
| 设置依据 | 固定规范、根据数据计算，还是人工判断 |
| 前后衔接 | 输入输出格式、通道、位深、坐标、样本标识、中间文件 |
| 结果核对 | 原软件结果、参考依据、误差要求、不适用情况 |

再查对应版本的官方文档、宏或脚本说明、必要的源码，确认这个功能实际做了什么，能否自动调用。操作记录说明“用户怎么用”，软件资料说明“功能怎么实现”，方法文献和参考数据帮助判断“这样分析是否合适”。三者不能互相替代。

在另一份数据上重复流程，再比较另一个实验室的差异。第一轮以少量有代表性的正常和异常数据验证，不把无限收集样本作为启动条件。调研交付的是能复现的流程说明，不只是软件名称列表。

## 3. 怎样封装成自动化模块

先做小实验：给定输入和参数，不经过手动点击，能否得到原软件对应步骤的输出？按实际能力优先使用已有算法库、官方接口、命令行或宏，确实没有可用入口时再评估界面自动化。具体入口、版本和分发条件要实测核验，不能假设所有软件都能直接内嵌。

现有实现不可用时，可以自行实现对应方法，但必须说明差异并重新验证，不能凭按钮同名就说结果等价。商业软件可能仍需用户安装和有效许可；界面自动化要说明依赖环境并能识别失败。

一个模块对应一个有意义的处理步骤，例如背景处理、对象分割、区域测量或图表导出。**不必把每次点击都拆成模块，也不必一开始拆到最细。** 一段不可分割的宏可以先整体封装，有真实复用需求后再拆分。

每个模块先讲清五件事：接收什么、允许设置什么、产出什么、使用什么方法版本、失败怎样报告。图像保留位深和坐标，测量表保留单位和样本关系，选区能对应原图。平台负责连接和调度，实验方法留在模块内部。

接入只加必要的适配：把平台输入转成原功能所需数据，调用功能，再把输出登记为下一步可读取的结果。继续使用现有公开接口和执行器，不为每个模块另建任务、恢复或缓存系统。只登记经审核的模块，不从任意路径加载代码。

## 4. 不同实验和实验室怎样复用

| 实际差异 | 产品处理方式 |
|---|---|
| 方法相同，参数不同 | 同一模块，保存不同参数预设 |
| 步骤相同，某一步方法不同 | 替换该模块或明确的方法选项 |
| 顺序不同，或者多一步 | 调整连接，另存流程模板 |
| 输入格式或仪器输出不同 | 增加读取适配，保留必要信息 |
| 特殊操作无法用已有模块表达 | 封装专用脚本或宏，遵守同样的输入输出约定 |

复用依据是数据和方法含义兼容，不是“都属于生物图像”。先跑通一个流程，再用第二个真实流程检验哪些部分值得共用。专用模块可以长期保留，不强求所有实验都变成通用算法。

调整也要有依据：有计算方法的参数，封装为计算步骤；有明确条件的选择，保存条件和分支；没有可靠依据的判断，提供可选纠正入口。不要让Agent自由猜测科学阈值。

正常输入按已配置模板全自动运行，不逐节点确认。无法可靠处理的样本标明原因，按模板策略暂停该样本或继续其他样本。用户修正后，从受影响步骤重算，保留旧结果。修正默认只属于本次运行，明确保存后才成为模板新版本。

## 5. 用户实际怎样使用

首次使用，用户选择接近自己实验的模板，导入一份数据，检查关键结果。需要时换方法、调整选区或参数，然后保存为“本实验室模板”。这是配置和验证阶段，后续不必每份数据重新配置。

日常使用时，选择模板，导入数据文件夹，填写该批样本分组或必要参数，点击运行。系统处理整批数据，显示完成、失败和需要纠正的样本，输出测量表和图表。

模板保存模块及版本、连接、参数、条件和输出规则；每次运行另存实际输入、实际参数和结果。模块升级不静默改变旧模板。定量数据与显示美化分开，显示用压缩或调色图不重新进入测量。

## 6. 后续按什么顺序开发

当前开发继续原任务。2026-11-02只读核对到实际开发树在做P-008批处理，后续P-009是可视编排。执行、恢复、失败隔离和可编辑流程都符合本方向，无需中途返工。本次没有重新验收代码；实际任务状态只看开发树任务卡。

后续两方面配合推进：已有平台任务继续完成执行与编排；新增实验功能按真实流程逐个交付。平台先提供已需要的连接和运行能力，模块范围由实验调研决定。

1. **选流程：** 确定用户、数据和目标结果。
2. **记操作：** 完成软件功能与操作清单，区分固定步骤和人工判断。
3. **先复现：** 在原软件重跑，保存对照结果，验证自动调用入口。
4. **做模块：** 复用已有能力，只补该流程缺少的操作。
5. **连模板：** 用现有执行器跑通单份数据，再运行另一批数据。
6. **核对交付：** 比较关键中间结果及最终结果，保存适用范围、模板和说明。

与原软件一致只是必要对照，原操作本身也可能不合适。因此还要用独立已知样例、参考标注或方法依据核验。比较指标和容差在看新实现结果之前确定，不为通过验收临时放宽。

先以已有WB能力验证这条路线，再选有真实资料的第二类实验检验复用。材料缺失只影响对应模块的方法验收，不冻结独立的执行器和编辑器。具体做法见[开发流程](workflow-development.md)，执行提示见[AI开发规程](../ai-workflow.md)。

## 7. 怎样算做对了

第一阶段目标：一条有来源、有对照的真实分析流程，能保存为模板，处理下一批数据，定位失败步骤，允许调整和复用。看跑通哪些真实流程、结果是否可信、重复操作减少多少，而不只看节点数量。

随流程增加，再提炼共用模块、扩展模板库，逐步加入有依据的自动判断。Agent可以辅助操作，不承担尚未验证的分析决策。先解决具体工作，再扩大覆盖范围。
