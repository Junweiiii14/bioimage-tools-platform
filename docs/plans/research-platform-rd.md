# 科研数据平台研发总方案

5.0 · 普通实验人员的完整自动分析流程 · 2026-11-06补充MVP、统一交互与图形化编排交付

> 产品方向：多实验工具＋统一平台＋Agent。以普通生物本科生、研究生和实验人员的实际任务为入口，先交付低门槛、可验证的完整实验分析，再扩展专业方法和可组合工作流。本文是开发方案，不能作为新功能、科学效果或商业收入已经实现的证明。

## 1. 产品定位与成功标准

用户要完成的是“把这批实验数据处理成可信的表和图”，通常不是学习算法名或搭建节点图。默认入口应按实验和目标结果组织，让用户知道要提供什么、会得到什么、哪里需要复核。

保留专业计算能力，通过明确的实验预设、必要信息收集、自动处理、质量提示和结果追溯降低操作门槛。简化界面不能省略会改变科学含义的输入，也不能把默认参数伪装成适用于所有数据。

本次方向依据是用户转述的身边实验室粗略调查：部分人员觉得CellProfiler操作困难，希望更简单。它是值得验证的需求线索，尚不是代表性用户研究、付费意愿或市场规模证据。我们不预设所有用户都会迁移，也不承诺与CellProfiler所有功能、版本及输入完全等效。

核心成功标准是：目标用户能独立完成一个明确的实验任务，结果在声明范围内经独立参考验证，出错时能理解原因并恢复。先验证这一点，再扩大实验覆盖。

## 2. 两种使用方式，共用同一套计算

| 使用方式 | 用户看到什么 | 开发要求 |
|---|---|---|
| 实验向导，默认入口 | 选择实验与结果 → 导入数据 → 补齐必要样本信息 → 自动运行 → 查看质量与结果 → 导出/重开 | 隐藏不必要的算法术语；模板内正常步骤无需逐节点确认 |
| 专业工作流，按需进入 | 查看实际处理步骤、调整参数、替换已验证模块、保存自己的模板 | 复用已交付的图编辑/执行基础；不能建立第二套公式、存储或运行语义 |

首版向导只暴露对结果有实际影响且不能可靠推断的信息。例如样本分组、对照与重复身份必须明确；文件名或Agent猜测只能成为待确认建议。系统应说明缺什么及其用途。

正常数据默认全自动完成。遇到超出适用范围、低质量或缺信息，标记对应样本与步骤，提供原因和最小纠正入口；其他样本按已选策略继续。人工纠正生成新修订，只重算受影响下游，历史成果保持。

结果页给出结果表、可追溯图像、样本/单位/质量状态、采用的方法与参数、导出和重开入口。预览和正式定量使用可追溯的一致分析来源；缩略图、RGB8、LUT等显示副本不能进入定量。

## 3. 开发顺序：先完整实验，再扩大覆盖

**调研任务与结果 → 固定输入输出和适用范围 → 选择并验证算法 → 做完整自动流程 → 普通用户独立使用 → 修正失败 → 扩展下一实验。**

一条完整流程包括导入、样本身份、必要预处理、分析、质量控制、统计/汇总、表图输出、保存重开及异常恢复。具体实验不需要的步骤不强加；不以算法跑通或一张漂亮截图作为闭环完成。

每轮只推进一条可交付主线。已有的WB、通用执行、批次恢复和可视编排继续复用，不推倒重写。第二实验的需求调研可以在不依赖未完成科学材料的范围内推进，但其产品实施应在首条学生流程的体验和验收边界清楚后拆卡。

当前采用“先可用流程MVP，再集中完善交付版本”的节奏。单实验MVP完成表示有实际入口、基本操作、真实执行、结果导出和重开，以及相应工程证据；不表示前端精修、真实学生试用、科学准入或用户安装版更新全部完成。按用户要求，一个实验的本轮MVP结束后，换新开发窗口推进下一实验，保留未验项，不将换窗口等同于科学验收。

本轮先完成WB、单图核分割及下一条经调研选定实验的MVP，再进入统一工作台与编排体验的集中完善阶段，安排在对外试用/交付候选之前。孔板调研继续；若未取得可实施证据，不为凑齐三个工具无限推迟已有工具的统一工作。每个新MVP从开始就遵守第11节的基本入口、状态和导航约定，精修集中进行，不允许积累不可发现的入口或另造执行语义。

“尽可能覆盖普通学生需求”是逐步积累模板的长期方向，不是首版同时开发全部实验。专业小众能力只有在真实场景需要、输入输出和验收明确时才成为新模块。

## 4. 每个实验先研究哪些事实

先确定一类具体用户、一个实验类型和一种目标结果。读取获准使用的SOP、原始记录及公开方法；有授权材料时观察熟练人员处理一批数据，再用另一批检验变化。暂时没有材料时只做候选设计，不虚构访谈或真实性验证。

| 要查清的问题 | 最小交付物 |
|---|---|
| 谁在什么情况下做、频率如何、哪里耗时或易错 | 用户与任务说明；实际观察和主观偏好分开 |
| 输入是什么，如何确认样本、通道、位深、尺度和分组 | 输入清单与数据契约；不能按扩展名猜实验身份 |
| 最终需要哪些数值、表、图及单位 | 一份具体结果样例和列定义；标明生物/技术重复 |
| 当前如何处理，为什么改参数或排除样本 | 操作与判断记录；保留失败和修正过程 |
| 原软件实际做了什么计算 | 对应版本、公式/源码/参数默认值、转换与边界 |
| 如何知道结果正确、普通用户能否独立完成 | 科学比较方案和使用任务，预先固定判据 |

同一份短实验说明承载这些内容，不为每个步骤建立新文档体系。详细实施规范见[开发流程](workflow-development.md)。

## 5. 算法策略：有效现成方法优先，缺失才自研

**成熟优质实现优先，先检索和实测，再决定是否自研。** 此准则适用于后续所有实验模块及算法研发Agent：任何新算法研发或现有简易基线继续优化之前，先检索适用的成熟开源实现、官方pipeline和预训练模型。复用已有项目代码不等于自有简易基线优于成熟方案；简单基线可以保留作诊断对照，不能取代成熟方案选型。

成熟且适用的方案优先通过受支持的API/CLI或封装官方实现直接调用，研发重点放在实验流程、质量反馈和易用性。采用前核对固定版本、接口、依赖、代码及模型权重许可、再分发和本地部署条件；用少量代表性数据实际对照效果、失败样例及CPU/部署维护成本。成熟不等于无需验证，也不能因算法同名或自行复写就宣称复用了CellProfiler等原工具。

| 路径 | 决策依据 | 必须保留的证据 |
|---|---|---|
| 调用现成实现 | 方法适用、调用稳定、依赖与分发可接受 | 固定版本/来源、实际参数、输入转换、真实调用与输出对照 |
| 复现公开方法 | 方法定义完整，现有实现不可用或成本不合适 | 原始定义、独立参考、逐步骤差异与容差；不夸大为全输入等价 |
| 自研或采用替代方法 | 现成方案经检索和最小实验证实不能满足具体需求，或无法合理集成 | 候选及具体不足、选择依据、替代方法版本、独立验证、适用范围及失败样例 |

不要为“创新”重复写成熟算法，也不要为“复用”引入无法维护的整套环境。需要外部软件时先验证安装、无界面运行、错误传播、离线条件和升级影响；有依赖冲突才考虑独立worker环境。界面点击自动化只在没有稳定接口且成本可接受时评估。

不能因尚未搜索、安装稍麻烦或单个候选失败就转入自研。选型依据简短记入现有任务/研究证据即可，不新增繁复审批表，也不要求用户反复确认普通实现选择；实际步骤见[开发流程](workflow-development.md)第3节。

专业度来自方法适用性、计算正确、质量控制和可复现证据。使用相同算法本身不能保证相同结果：位深、预处理、默认参数、坐标、阈值、单位和统计设计都可能改变答案。

## 6. 平台、模块、模板与Agent的边界

实验模板是经过验证的一条完整操作流程；算法模块是其中有明确输入、参数、输出和失败语义的可替换步骤。模块粒度按计算职责划分，不按每次鼠标点击划分。

平台只管理通用资产、图规则、运行/取消/恢复、结果提交及版本。实验模块负责本实验方法和必要交互；外部只走公开API。不同用户的参数差异用预设，方法差异用版本化模块，流程差异用模板，格式差异用适配器。只有真实复用证据出现后才提炼新公共包。

Agent按成熟度逐步接入：先解释结果和错误、帮助找到合适的已验证模板；再把用户意图转换为可检查的参数/工作流草稿；最后才评估受控调用。所有执行仍走同一确定性入口、真实输入验证、冻结计划和结果提交。

Agent不能自行认定生物学分组、科学真值或统计设计，不能静默猜关键参数，不得任意加载工作区代码。自动调参只能调用已验证的规则并保存本次值及依据。缺少Agent、网络或模型服务时，已交付的实验模板仍应能本地运行。

算法研发Agent属于后期辅助研究：提出候选、生成可审查实现和测试，不能自行把候选算法提升为正式默认。

## 7. 科学正确与使用简单，分别验收

| 验收维度 | 证据 | 不能替代它的东西 |
|---|---|---|
| 工程可靠 | 真实输入、worker、取消/恢复、正式成果、重开和安装验证 | 模拟按钮或只跑纯函数 |
| 方法正确/适用 | 独立参考、冻结参数、预先定义指标与容差、未用于调参的数据 | 新实现和自己对比、与原软件一致就宣布科学正确 |
| 普通用户可用 | 目标用户独立完成任务，记录成功数/总数、耗时、求助、误操作及纠正 | 开发者熟练演示、好看的界面、未经核实的满意度 |
| 可维护 | 方法来源、公开入口、调用路线、相关测试和版本迁移可定位 | 文档页数、节点数或抽象层数量 |

首次试用前明确任务难度、样本数量、允许帮助、成功定义及目标值；目标值基于实际基线或负责人依据，不事后降低以宣布通过。记录严重误用，即使任务最终完成也不能当作无风险成功。小样本探索不宣称总体成功率。

科学真值或目标环境缺失时，可以完成明确标记的工程候选，但不能宣称相应验收已通过。D1评估设计就绪不等于S1科学准入。当前[验收缺口](https://github.com/Junweiiii14/bioimage-tools-platform/issues/57)必须继承。

## 8. 分阶段推进与退出条件

| 阶段 | 主要交付 | 进入下一阶段前需要什么 |
|---|---|---|
| 0，旧事项收尾 | 依赖/旧PR、任务证据、阅读入口已整理；PR54/56已集成 | 已完成；真实未验项继续跟踪，不重启P002/M1/M2 |

| 2，首条学生自动流程 | 复用现有WB基础完成实验向导与完整输出；若资料不支持则先记录阻塞并论证调整 | 工程、方法、用户三类证据分别明确；严重错误/误用有处理结论 |
| 3，第二实验闭环 | 经需求比较选定的一个实验，验证模板和接口的真实复用 | 独立完整流程通过其验收，扩展没有污染平台实验边界 |
| 4，扩大普通实验覆盖 | 按需求与材料优先级逐个增加模板 | 每次有真实使用与维护反馈，再决定下一项 |

| 6，受控Agent与机构交付 | 先辅助，再草稿，再可核验执行；按需求补部署和支持 | 确定性模板稳定，质量/隐私/成本边界可证明 |

这些是产品推进顺序，不是强制串行等待所有外部资料。需求调研、方法小实验和无关工程可并行开展；缺项只阻止依赖它的结论。当前仅登记下一项[P010需求与流程调研](../../work/tasks/P-010-experiment-discovery.md)，后续按实测结果拆小任务，不预建几十张空任务卡。

首个验证入口建议沿已有学校实验室关系，从WB完整学生任务开始，理由是已有工程基础、切换成本较小；这仍需真实需求与材料确认。IF计数/强度等属于第二实验候选，不在没有比较证据时固定市场结论。候选和选择规则见[实验路线](experiment-research-roadmap.md)。

## 9. 成本与经营验证不脱离产品

用户资金紧张，希望尽快有人付费、覆盖开发成本，并以一年净利润超过十万元为目标。该目标保留为商业假设，不是本方案能保证的结果。

先用已有老师和企业联系人作为用户自行协调的调研入口，验证谁使用、谁付钱、谁验收，以及部署/维护成本。可优先测试有限范围的付费部署、适度定制或技术服务；是否订阅、软件收费、免费试用及是否成立公司，待真实交付与采购条件核实后另作经营方案，不先构建收费系统。

每项试点都应有明确数据范围、成果、验收、支持边界与维护成本记录。不同实验室的共性再沉淀成产品模板；一次性定制不直接污染通用平台。没有付费证据时不声称找到可盈利模式，不自动对外联系、花费或上传实验数据。

## 10. 维护、版本和阅读入口

原始输入、已完成结果和初始PDF不可覆盖。改变公式、预处理、默认参数或schema时版本化并说明旧数据兼容；新几何方法沿[P004](../../work/tasks/P-004-analysis-asset-contract.md)独立验证，不能用旧显示角改变历史数值。未检测、无效、排除、失败与真实零值保持区分。

每次交付同步维护“用户动作 → 公开入口 → 方法/适配 → 输出 → 相关测试”的短导航。复杂度来自真实问题时才重构，不为假想扩展创建框架。实现、验证和长期维护要求见[维护计划](../maintenance-plan.md)。

## 11. 统一界面、图形化编排与实际交付

2026-11-06用户要求补齐前端规划，并明确需要类似Coze的图形化节点编排体验。这里指节点画布、连接、配置、运行反馈的交互方式，不承诺复制第三方全部功能。采用操作型桌面界面，沿用当前DESIGN.md的配色、字体、密度与动效，避免重做品牌或无依据换组件库。

### 11.1 当前事实与阶段划分

P009已交付有限模块目录、节点增删/替换与连线、参数表单、模板保存重开、实际执行和中间成果，见其objective-audit；不重写画布或执行器。它不代表每个新实验都已注册成节点，也不代表任意模块可互连、性能达标或Agent编排已实现。P016的核分割入口为单独横条按钮，WB为工具卡片，统一视觉尚未完成。PRODUCT.md仍有仅WB的旧描述，应在统一实施时按真实代码更新，旧历史证据不改写。

| 阶段 | 安排与退出条件 |
|---|---|
| 单实验MVP，当前主线 | 继续下一实验调研与最小闭环；已实现工具入口可发现，基本运行/取消/失败/导出/重开可用。状态明确为工程MVP或研究候选，不称交付完整版 |
| 统一工作台与编排，随后集中实施 | WB、核分割及下一选定MVP范围明确后，优先统一首页/导航/结果/设置，再完善现有节点画布与可注册模块；不等待无限实验覆盖。按真实范围拆小任务、独审和集成 |
| 可交付候选，试用前 | 从同一准确提交准备可启动候选，真实核验用户入口、首次准备、完整操作与重开；记录版本/通道和实际启动路径。准备候选与替换用户安装分开，正式发布或替换仍按既有授权 |

以后汇报分别写“源码/工程MVP”“统一交互验收”“候选可运行”“用户安装已更新”“科学/真人试用”，不能用一个“做完”代替。未经实际更新，不能称桌面快捷方式已包含新功能。安装版本标识和帮助入口须让用户能识别正在用哪一版。

### 11.3 类Coze的专业编排入口

默认实验向导与专业编排是同一实验定义的两种使用方式，不建立两套公式/存储。入口命名“工作流编排”，从工作台可发现；项目中能查看对应受支持流程。尚不能映射到图的旧项目明示范围，不假装支持无损切换。

- 左侧模块目录：按输入、处理、分析、结果输出分组，搜索已注册且有明确契约的模块；区分实验适用范围和研究状态。
- 中央画布：节点选择/移动、端口连线、删除、缩放/平移与适应视图；节点显示输入输出和真实状态。无效连接说明具体原因，不能只靠颜色。已支持的交互复用P009，不因布局改动重算。
- 右侧配置：选中节点编辑必要参数、单位、默认值依据与适用范围；专业项按需展开。原图/显示图、位深、坐标、单位和样本身份必须遵循既有端口契约，不允许“看似能连”但科学含义不兼容。
- 运行与结果：稳定显示运行/暂停或继续/取消、预检错误定位、中间已提交成果与最终输出；仅展示实际支持的控制动作。错误可定位节点，日志细节按需展开，旧运行不能覆盖新草稿。
- 模板：保存、重开、另存模板以及用新数据运行；定义、参数、模型/方法版本与布局可追溯。向导模板来自同一执行定义，专业修改不静默覆盖原模板或历史结果。
- 接入次序：先验证既有WB编排，再让核分割及下一实验中契约兼容的模块可注册/组合；实际不兼容则禁止连接。多实验“可组合”不等于把无科学联系的WB输出硬接核分割。Agent生成草稿与受控执行仍属后续阶段，不因画布完成而默认启用。

### 11.4 验收与后续责任

统一实施前从本节拆一张当前有依赖依据的任务卡，不预建几十张空任务。上游负责在当前MVP批次结点派发；各实验窗口将可复用的真实模块、界面缺口和未验项交接。每个实验换窗口的偏好保留，平台统一任务单独协调，避免多个窗口同时修改共享前端。

验收使用真实桌面入口：WB与核分割各走一条导入→运行→表图→重开；在编排画布执行节点编辑/连接/参数/模板→实际worker→成果，并覆盖无效连接、取消、失效和旧结果保护。截图/演示只证明展示，不能代替真实操作或科学准确性。视觉检查先批量覆盖主要状态/1440与960/现有主题，集中修复后最多一次确认，不无休止润色。准确提交独审、相关回归及既有必需CI正常执行；源码、安装候选与实际用户安装分别记录版本和结果，不因文档更新触发产品验收声明。
