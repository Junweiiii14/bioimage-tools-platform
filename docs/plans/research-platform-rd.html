科研数据平台完整研发总方案

版本 4.0 · 2026-11-02 · B-009 · 模块化工作流平台研发依据

最终产品是面向生物实验室、类似 Coze / ComfyUI 编排体验的模块化数据处理平台。实验人员可以组合算法模块，保存为适用于自己实验条件的固定工作流，之后用新数据无人值守重复运行。WB 是首条参考工作流和现有能力来源，不是产品边界；IF、计数、板式实验是检验复用的消费者，不是分别重做一套软件。

本版主线：模块目录 → 类型化数据与连接 → 确定性工作流引擎 → 可视化编排与模板 → 批量自动运行 → 特殊实验扩展。 AI 后续帮助选型、搭建和研发，但固定流程不依赖每次由大模型临场决定步骤。保留 Qt 宿主、现有 WB 计算和工作区可靠性，逐步迁移，不整体重写。

相对3.0的实质调整：可视化编排成为核心交付；第二场景工程切片提前验证复用；专用模块接入不再等待算法研发 Agent；将平台工程进度与单个实验的科学准入拆开。第7/8章保留十类实验的方法、数据和限制，第9章说明能力覆盖与扩展，第12/13章替换原先按WB→IF→计数串行扩展的排期。旧V0–V7仅保留为能力标签，不再代表必须顺序完成的版本队列。

本文明确区分已实现源码、当前任务记录和待实施设计。计划完成不等于产品功能完成；本轮只改文档和交接，不修改产品树、不发布软件、不自动激活所有后续实验开发。旧版见 3.0归档，本版证据见 B-009任务。

1. 最终产品具体是什么§

1.1 三类用户，共用一个工作流§

普通实验人员选择经过验证的模板，绑定样本表和数据，检查一次输入是否齐备后运行；熟练人员进入编排视图，添加/替换模块、连接端口、配置参数，并保存成实验室模板；方法开发者编写专用节点或封装已有程序，经验证接入目录。三类入口共用同一个流程定义、执行服务和结果来源，不各自生成独立答案。

例如：导入多通道图像与样本设计 → 输入质控 → 选择检测通道 → 核分割 → 对象过滤 → 在指定测量通道统计强度 → 按样本/生物重复汇总 → 图表与报告。核计数模板可以复用前半段并改接计数模块；特殊细胞结构可以替换分割方法。对象种类、坐标、通道、单位及统计层级仍须校验，连得上不等于科学上可比。

1.3 自动化的产品承诺§

自动化针对已声明的输入范围和已冻结方法，不承诺任意实验都自动给出有效结论。模板保存规则而不只是固定数值：参数可来自常量、样本元信息或版本化自动估计器，估计的实际值和来源必须逐次记录。缺少分组、配对、参考或实验端点时先补齐；不得根据图片或文件名猜生物学关系。

正常批次不要求逐节点确认，也不要求手动旋转。正式几何校正必须产出保精度分析资产，预览、ROI和定量共源；未知角度不得默认为有效0°。异常样本自动隔离，独立样本继续，最终标partial或failed并列出缺项；人工修正是可选恢复路径，不伪装成已经无人处理成功。

目标依赖与拆分粒度§

首版继续使用现有四个包。tool_contracts只容纳不依赖Qt、NumPy、SQLite的信封与结构描述；platform_runtime处理通用资产、状态、依赖与恢复；wb_tool拥有WB定位、极性、基线、条带和归一化；bioimage_app静态装配工具、进程、存储与界面。跨包只走各自api.py。平台不得出现蛋白、Ct、内参或阳性面积等实验分支。

先把WB封装为少量有科学意义的粗模块，再按真实复用和暂停需求拆细。V0粗模块只包装成熟旧计算；V1候选粗模块可包含“自动校正—生成ROI—测量—成果生成”，内部发阶段事件，但不能宣称每个内部函数都已是可恢复节点。后续拆成校正资产、ROI与测量、统计与导出三个边界，必须先把每个边界的输入、提交物和失败恢复做完整。第二工具真正接入后，才评估把共同几何或图像I/O抽到imaging_core；不预建大量空公共包。

现有AssetRef@1保持不变。拟新增ScientificAsset@1组合它，记录语义类型、坐标、单位、来源与方法；设计中的FileRef只表示该物理引用角色，不是悄悄替换现有模型。已有最小ModuleSpec@1、ExecutionRequest@1、ExecutionEvent@1、OutputManifest@1需按兼容策略扩展；新增科学语义与物理存储格式分别版本化。图像、表格、曲线、对象和统计结果均通过资产引用传递，不能把数组嵌进Qt桥接消息。

切片范围是一个Fig、明确目标/内参配对、固定样本槽位的灰度TIFF输入；身份映射通过导入模板一次提供，不依赖文件名猜测。默认路径为导入→自动估计倾斜→生成保精度分析资产→自动ROI/积分→表格与拼图。无需工作人员旋转一次，更不能要求两次旋转。首先作为带清晰方法标签的候选入口运行，完成科学验证后才成为正式默认路径。

  1. 冻结输入和旧答案。 用不含私有数据的小型uint8/uint16固定样本，保存原图hash、既有分析结果及输出hash。加入已知平坦、饱和、空槽、0°和已知几何的独立参考。旧数值作为兼容对照；新插值方法的正确性不能只拿旧矩形答案判断。误差指标与容差须先写方法契约，不能从运行结果反推通过线。
  2. 先跑通薄适配。 实现矩阵1–3和一个粗模块，用旧analyze_annotations完成冻结输入到旧结果的等价调用；新信封只负责引用与版本，不在此时偷偷改变公式。为api.py导出、模块注册和独立wheel补齐检查。
  3. 实现统一分析资产。 候选角度经适用域检查后，从不可变原图一次重采样，产出float64分析数组、有效区mask及JSON描述。首版可用已有NumPy的受限NPY格式，关闭pickle；预检shape、dtype、字节预算，禁止对象数组。描述保存源hash、角度、变换矩阵、插值/边界策略、采样格点、方法版本与软件版本。float64是明确编码选择，不是“插值无损”的承诺。
  4. 在分析图上建立ROI并计算。 自动定位输出绑定分析资产的ROI；人工修改是可选接管。无可靠角度输出unknown，进入该Fig待处理状态，不把0°当检测成功。mask覆盖不足或区域超界必须有失败/待处理理由，不能把填充值用于积分。初版不把任意历史矩形自动转成新ROI；选择旧记录重算时重新定位，必要时由用户处理明确异常。
  5. 用真实worker接宿主。 拟新增静态路由--worker wb_analysis_v2及W/adapters/analysis_worker.py，复用ProcessRunner/RunSession退出与取消链。该粗模块内部阶段可报告进度和预览，但首版只在整个模块提交后形成可恢复节点。worker只写宿主为本次attempt分配的暂存目录；宿主校验清单、导入不可变资产，实际退出成功后提交结果清单。
  6. 交付可观察的一次运行。 新工作台入口展示当前步骤、已提交/候选标识、曲线与图；worker忙时仍可浏览其他结果。CSV/XLSX及拼图引用同一分析资产和参数修订；与内参的配对由明确样本身份决定。先按单进程序列执行，不以并行度换取状态复杂度。新策略中的独立Fig允许继续，最终批次状态清楚列出缺项。
  7. 用真实操作验收。 从导入走到打开表与拼图；运行中切换页面和查看曲线；取消后重开；修改角度候选/ROI后重算；只改字体后重新导出。核对旧原图/历史hash不变、当前修订不被晚到结果覆盖、图和数值共源。界面“成功”只对应完整结果提交。UI可操作与科学方法准入分别验收，候选结果不自动进入正式汇总。

工作流、worker与存储迁移的具体边界§

首版不升级SQLite。 Workspace现有数据库格式v1含五表，并允许保存opaque JSON。将定义、工作流运行账本保存为新的版本化文档；每个计算attempt仍对应真实RunRecord。账本先保存attempt身份与冻结输入，再启动进程；进程结果成功提交后，账本CAS关联结果引用，最后通知UI。若崩溃发生在结果已提交而账本未关联之间，恢复按attempt/process_run_id核对已提交结果并补关联；不得直接重跑或编造成功。没有确定提交结果的attempt为interrupted，由重试生成新attempt。

资产导入、结果文件发布与账本更新不是一个跨文件/SQLite原子事务。未关联资产或结果保留为待恢复/孤儿证据；只有清单引用、摘要校验与结果提交均满足后才可供正式下游消费。存储线程仍独占Workspace；worker、Web前端和Agent都不能直接写库。图级run不是OS进程，不能把图ID或伪PID塞进现有RunRecord。

协议双轨。 旧worker协议的ResultFrame仅接受8/16位及相应范围（W/application/worker_protocol.py:78），不能把派生float伪装为16位图。新增协议使用ScientificAsset引用、明确量程与数值方法，保留旧命令/帧模型。新事件有run/node/attempt、单调seq和冻结修订；状态/终态可靠处理，预览允许合并或丢弃。容量策略分路由配置，限制单帧、队列、频率和预览尺寸，不是把旧最大8帧简单放大成无限流。丢弃过期UI事件不等于丢弃进程退出、清理和持久化责任。

历史与新语义并行。 W/application/crop_suggestions.py:125 read_figure_project继续读取既有schema1–15；新工作流使用独立文档类型。旧display_angle只按旧显示含义读取，不能静默解释为定量校正。用户选择新方法后创建新分析资产、ROI与运行，旧结果和方法版本仍可打开。规则“显示变换不进入定量”继续适用于字号、排版和显示色阶；新的自动几何校正是显式版本化分析步骤，预览与定量共同消费其输出。

确需数据库v2时再迁移。 当事件查询、节点规模或并发需求证实opaque文档不足，再增加workflow_runs/node_attempts/artifact_links等表，给出DDL、索引和回填程序。关闭活动任务、独占锁、调用现有Workspace.backup创建一致备份，在新目录副本迁移；带迁移未完成标记的目录拒绝正常打开。数据库事务、资产核对、格式头写入全部成功后才发布新目录；失败保留旧工作区与待诊断副本，不假称文件和SQLite整体原子。禁止直接复制活动DB主文件或原地覆盖历史；旧客户端应拒绝新格式。并发及云执行需要新增资源租约/远程终止凭据等协议，不能冒充本地exit receipt，均不进入首切片。

强度不由分析 dtype 推断。首版 WB 的 16 位采集图旋转成为 float64，强度范围仍来自采集定义；反相上界显式绑定 acquisition range，而不是 float64 最大值或每张图自己的峰值。采集位深和量程来源未知时记 unknown；若方法使用容器名义范围，必须明确它不是已核验的仪器有效量程。float32 作为后续独立验证的存储/计算变体。插值产生的边缘空区用 mask 表达；真实零像素与无效像素不同。饱和证据继承原像素质控，不能因插值后的数值变小就消除警告。

3.4 一个模块的实现形状和连接校验§

现有 tools/wb/src/wb_tool/application/module_execution.py 及同名adapter已提供V0粗模块。以下是后续完整适配契约草图；仅在需要时再拆文件，不重复创建另一套旧方法适配器：

class ModuleExecutor(Protocol):
    def describe(self) -> ModuleSpec: ...
    def validate(self, inputs: InputMetadata, params: FrozenParams) -> ValidationReport: ...
    def execute(self, request: ExecutionRequest, context: ExecutionContext) -> OutputManifest: ...

# context 仅提供受限资产读写、取消检查、进度/预览发布。
# execute 的纯计算交给 domain；worker 适配器负责 I/O。
# domain 不获取 Workspace、Qt、任意文件系统或网络客户端。

wb.measure_float 的 image 端口要求 analysis_image、二维单通道、首版 float64、采集强度单位和有效 mask；rois 要求 geometry 且 frame ID 相同。输出 wb_band_values_v2 与完整 series。它包装新方法 wb.measure.profile_integral_analysis@1，与模块 wb.measure_float@1.0.0 的接口版本分开。新分析方法从旧算法数学定义迁移，但不用旧整数入口偷偷截断浮点；旧 wb.measure_integer 包装原有方法语义，继续读取旧历史样例。

连线判定分四层：schema 与端口 kind → 元信息 axes/dtype/unit/frame → 样本/配对/行身份 → 方法适用域与准入。geometry/mask还绑定依附的analysis_asset_id及revision；恰好同shape/frame的另一原图不能借用ROI。跨通道复用要求显式配准或共享frame的来源证据。首版WB要求量化ROI内valid_mask全真；插值后一个像素只有全部非零权重的源像素均有效才有效，部分无效ROI拒绝定量，不静默排除后更换分母。预期负例必须包括 display→measure、不同 frame/资产的 ROI、缺内参配对、未知 schema、包含环和未注册模块。转换只能通过显式节点发生，例如单位换算或坐标映射，不允许 runtime 猜测。

3.5 运行与重算的实际语义§

工作流实例、节点尝试、底层进程是三个身份：workflow_run_id 统领一个冻结草稿；node_id + attempt_id 区分重试；现有 RunRecord.run_id 只表示真实 worker 运行。映射保存在宿主账本。V2 使用串行拓扑调度，复用 Workspace.start_run 当前一个活动进程的限制，绝不伪造 PID 或放宽成功提交规则。每节点先用独立 worker，只有实测启动成本值得优化时再设计长驻 worker；不能先假设一个进程可提交多个旧 RunRecord。

用户动作/事件 后端动作 界面行为与结果保护

暂停 首版仅节点边界：running → pausing；停止派发；当前节点完成提交或失败并确认进程退出后，工作流进入 paused 立即显示“正在暂停，当前步骤结束后暂停”；界面仍可操作；暂停完成后才显示 paused；底层 RunRecord 不新增伪 paused 终态

节点级重启是第一版恢复能力。模块若声称支持节点内部 checkpoint，还必须声明 checkpoint schema、算法/输入版本匹配和安全点，证明恢复结果与从头运行在预定容差内等价。没有这项证据就从节点头重算，不标记“断点续算”。

缓存键由规范化 JSON 计算 SHA-256：模块/方法/模型版本、implementation_digest（源码发布包+锁定依赖+模型摘要）、输入科学资产描述摘要及全部载荷摘要、冻结参数、相关环境指纹、种子。采用项目规定的键序/数值规范，拒绝 NaN/Inf，不使用 Python hash()。显示缩放、面板展开不进入分析缓存。运行准入与权限在复用缓存时仍重新检查；被撤销的方法不能靠旧缓存进入新的正式结果。

具体失效例：改导出字体，仅重做 compose/export；改内参配对，重做 normalize/export，若图版显示配对标签也重做 compose；改 ROI，重做 measure/normalize/compose/export；改角度，重做 correct 及所有下游；只放大画布，零分析节点失效。模板必须声明各节点读取哪些参数；不允许拿整个项目 JSON 当缓存键造成所有编辑全量重算。

3.7 从可视图到可执行计划：编排器的职责§

拟议对象分开版本化：WorkflowDefinition保存可编辑节点、端口连接、参数绑定和对外端口；WorkflowLayout只保存画布位置、缩放与折叠；ExecutionPlan是输入绑定、子流程展开、参数解析、模块/依赖摘要固定后的执行快照；WorkflowRun保存实际attempt与产物。第3.1节及第10章的WorkflowSpec是流程契约总称，具体可编辑表示即WorkflowDefinition，编译结果即ExecutionPlan；实施时统一名称，不并行维护两种图语言。它们是设计名，当前最小ExecutionRequest不等于这些已实现。

编辑器从ModuleSpec生成控件，不允许直接提交Python表达式、任意命令或导入路径。保存模板可以存在未完成字段，启动必须全部通过：schema/缺节点/环 → 必需端口与类型 → 单位、坐标和身份 → 模块方法适用域 → 资源与权限 → 必需成果可达。静态信息不能证明的条件在输入解码后、进入相关节点前再校验；未知不能按通过处理。

首个图编辑器支持有向无环图、增删节点、替换兼容实现、连线、参数、撤销、保存/重开、运行状态及成果定位。模板是预装工作流，子流程是可展开的工作流封装，算法模块是执行边界；不把这三者混成任意函数调用。子流程显式暴露输入输出和允许调整的参数，内部版本固定，修改产生新版本。

批量先用有限样本清单展开节点，保留稳定sample_id和node_id，不先引入任意循环语言。第二阶段加入有类型的条件分支、集合映射和聚合：跳过与失败分别记录，汇聚节点声明接受何种终态及完整性策略；生物分组属于模板设计输入。一个失败内参阻断依赖它的比值，不能阻断无关样本，也不能被汇总器当作有效零值。

UI只是同一计划的编辑器，CLI/模板/AI都走同一编译与校验入口。用户移动节点不使计算过期；改检测参数使检测与下游过期；改排版只重导出。运行中编辑产生新草稿，安全节点边界暂停后形成新修订/计划，旧attempt只能提交到旧运行，不能覆盖新草稿。

5. 交互过程：实时可见、可操作、可接管§

5.1 改动数据通道，动效才能反映真实工作§

目前宿主 QTimer 每 180 ms 检查状态变化并经 WebChannel 推送 stateChanged，worker 协议只有少量终态型事件且总帧数有界；这支持现有任务，不足以表达多节点连续预览。新协议必须独立握手版本。旧 worker 继续旧路径，新 workflow worker 使用流式事件；不能只把原有 8 帧上限改成无限。

5.2 既有项目中的三个逻辑阶段与状态栏§

批次、过程、成果是既有项目步骤中的三个逻辑阶段：配置文件/样本/模板，查看步骤与图像/曲线并接管，核对表图与导出。沿用第4章实际顶栏、步骤页签和工作区，不再建立平行三屏或新的常驻导航栏。它们共享workflow read model，不各自启动独立计算。状态栏显示当前批次、运行数、异常数和暂停/取消，不因切换页面丢失任务。

拟新增 apps/desktop/src/bioimage_app/workflow_controller.py 管用户意图和异步命令，workflow_projection.py 把事件投影为 UI 小快照；Web UI 增加流程视图组件与桥接命令。WB UI 保留 ROI/条带等专用编辑器，首版通过宿主内部窄端口挂载；第二工具证明复用后再抽 desktop_sdk，不把实验控件放入 runtime。

参数调整用草稿，不在滑动过程中逐次启动正式计算。快速预览请求带 generation，采用最新请求胜出；正式“继续”冻结参数一次。旧任务完成后可以进入历史，但必须带旧 revision，不能改写当前表或把用户刚改的 ROI 弹回去。后端完成前按钮显示接收命令/等待安全点，禁止用禁用整个窗口避免竞态。

5.3 动效、性能与验收脚本§

动效沿用现有motion服务与120/220/320ms等token，只用于面板/容器状态；科学图像、ROI、曲线和数值不做交叉淡入、位移动画或数字滚动，已完成预览一次替换并标版本。状态更新保持滚动、焦点和选择，减少动态设置优先。进度依据真实计数；节点切换不跑虚构加载条。缩略图缓存、列表虚拟化、分片加载和增量消息优先于视觉润色。

初始产品预算：常规点击获得视觉反馈 p95≤100 ms；运行中切换页/选节点 p95≤200 ms；取消/暂停命令确认 p95≤200 ms；新预览从宿主可用到 UI 呈现 p95≤500 ms。它们是待验收目标，不是已实现成绩；记录测试主机/屏幕缩放/样本大小/冷暖启动，任务完成耗时另报。取消完成时间受当前算法安全点限制，单独测量，不能混作按钮响应。

固定体验样例包包括：20 张典型 WB、200 张压力批次、一张超大图、损坏图混入批次、计算中连续改参数和切换样本。所有数据是获授权或合成，典型规格按真实客户样本登记。历史 R09 上限合成场景曾出现 15–27 MB 快照和约 0.5–1.2 s 点击派发；这说明应减少快照载荷，不代表普通客户实际延迟。

用户体验验收：运行时拖动窗口、查看上一张图和完整曲线，软件继续响应；暂停后改一个 ROI，继续后只有该样本及依赖汇总改变；取消先于最终提交生效时不得再冒出成功，提交已先完成时取消返回“已完成”并保留真实历史；关闭重开后能看到上次完成的步骤和中断原因。工程验收同时记录事件序号、revision、延迟和进程退出，不能只靠录屏看起来顺滑。

6. 实验人员微调：动作、作用域、重算与撤销§

微调的产品定义与默认体验§

实验人员说“这个结果需要调整”，可能是在修正实验身份、纠正自动识别、选择合适的科学方法、处理异常、改变汇总口径或准备论文图。旋转只是几何调整中的一项。软件必须能表达他们想改的对象和范围，说明会影响哪些结果，并把修改真正送入计算和成果链。

正常流程继续默认自动。实验室模板已具备必要样本关系和方法设置时，导入即运行；人员可以在任何页面浏览已完成步骤，并在需要时主动编辑。不能把每个参数都变成必填表单，也不能每步要求批准。新实验首次创建模板时，只收集图像无法推断的信息，例如样本身份、实验组、内参、板位和预期成果。

所有工具使用同一编辑节奏：选中对象 → 在原位工具区或抽屉修改 → 查看预览与影响范围 → 应用并重算 → 对比新旧结果。显示偏好可即时生效；影响实验结果的修改先成为草稿。批量应用多一个“应用范围”选择，但不额外复制一套编辑器。运行中仍可浏览、筛选、复制已提交数值、修改非冲突显示设置；科学修改可以先形成草稿，应用时等待声明的节点边界。当前版本的忙态禁用不是未来全部能力已经存在。

同样的微调，三种时机的处理逻辑§

运行前：调整模板生成批次草稿。输入改动会让预检重新计算支持范围、缺参和预计成果；“开始处理”绑定冻结草稿。被选择的模板版本不可被后台更新悄悄替换。

运行中：人员可以查看任何已完成对象，不随当前进度自动跳页。修改先留在本地草稿；点击“应用并重算”时显示影响摘要，停止派发，在当前节点终态和真实进程退出后保存新revision并生成新的执行计划。首版采用此清晰的节点边界，减少并发重算错误；界面继续可浏览。耗时不可中断算子可选择取消当前步骤重来，按钮必须说明这一后果，不能把请求已发出显示成已暂停。

运行后：通过“修改并生成新版”进入相同编辑器，读取旧参数和原始来源。只把不受影响且方法仍准入的资产作为缓存；新结果使用新run ID和方法/参数来源。用户可并排查看旧版与新版，差异表显示变化对象、数值、有效n及新增/解除的质控问题。

自动结果、人工纠正与模板之间如何组合§

默认策略生成可追溯的自动候选；人工编辑保存为对该输入版本的约束，优先于同一输入上的自动建议；“恢复自动建议”明确移除所选约束并重新运行相应自动模块。顺序是模板默认 → 当前批次设置 → 当前对象覆盖，覆盖字段逐项可查看，不靠“最后一份字典更新”隐式决定。

人工修正ROI只绑定当前图像资产与坐标；换原图、重做几何或重定位通道时，旧覆盖要经显式迁移/校验，否则标“需要复核”。不能把旧图x=100的框原封不动应用到不同尺寸或倍率的新图。跨图复用使用归一化几何、物理单位或已验证的配准变换之一，并记录模式；变换不是自动可比性的证明。

把修正“保存为模板”需说明哪些是可推广规则，哪些是当前样本的事实。阈值/方法和版式可形成实验室模板；样本名称、具体对象mask、单孔排除和一张图的坐标默认不入模板。Agent可建议把反复出现的纠正做成模板候选，但不能因为一张图修正过就全实验室生效。

批量应用与复用的准确规则§

批量操作先生成兼容性报告：选中数量、可应用数量、不可应用原因与受影响成果。支持“仅应用到兼容对象”时，将明确的兼容ID集合与apply_policy冻结到请求，receipt逐对象记录；不支持部分应用的方法采用全批拒绝。同一文档以一次CAS原子应用选定集合；跨文档是多个独立子操作，各有状态和回执，不能声称跨项目原子事务。相同operation ID重试不得重复叠加变换、重复扣背景或再次拆对象。

作用域按稳定ID冻结，不按当前页面第3行之类位置描述。排除/恢复、标准浓度等科学修改不能在排序后落到别的孔或样本。物理单位的参数在有校准的不同倍率图上可以换算；像素参数只能用于模板声明的相同像素语义。没有尺度时不能猜一个换算倍数。

三个完整交互故事及拒收反例§

故事A：一批WB到表格、拼图和异常清单§

实验人员导入三张膜的目标/内参原图和泳道表，选“已验证目标/内参模板”。软件自动检查来源，估角、转正、定位、出剖面和结果；过程页可以点击已完成的第一张图看基线，其他图继续。正常膜不要求任何确认。一张图估角不确定时只暂停该图依赖，明确显示不能判定原因，不默认为0°；批次仍能交付其他图和异常表。

人员发现第二膜第三泳道ROI略宽，主动接管并缩窄，再把一个OCR误识别的显示别名修正。界面告诉他ROI会更新该带及对应相对量/组图，别名仅改图表标签。应用后只重算依赖，旧版仍能打开；最终导出原量值、配对比值、组统计、拼图、剖面和异常说明。若源饱和，选另一张经过模板可比性检查的低曝光采集；不存在合格采集则报告未定量，不能用“自动修复饱和”解决。

拒收：调暗预览后饱和标记消失；角度失败显示“已校正0°”；跨膜只因泳道名相同就自动配内参；改目标名后旧量值直接被重标为新蛋白；取消后旧结果覆盖新ROI；缺拼图仍称整批成果完成。工程算例：目标120/参照60得2，对照90/90得1，归一后2；参照缺失必须null，不能以1兜底。它只验公式与身份，不验真实生物准确率。

故事B：二维IF从通道与背景到可解释组图§

人员导入两个处理组的多个生物样本，每样本若干视野。模板用结构通道定ROI、目标通道测强度，自动关联采集信息，完成区域/视野表及组图。人员点击一个偏高视野，看到背景环带被邻近细胞占满；软件已经把校正量标为待处理，没有给出一个漂亮高值。人员在模板允许范围内选已定义背景区，预览即时显示新B及受影响ROI，再应用继续。

随后人员把一个ROI和邻近ROI合成并集。系统去重交集像素，并重做与该前景遮挡相关的背景，更新该视野与对应生物样本；其他样本缓存可复用。最终图明确每点代表生物样本，视野数和排除数另列。导出保留原均值、背景、N、校正均值/总和与证据图，别人能知道变化来自信号还是区域/背景定义。

拒收：把合成RGB当原通道；结构图与目标图错配却因尺寸一样通过；只保留亮像素再宣称总表达增强；两相交ROI的面积直接相加；负校正强度截0；把同一样本的十个视野写为n=10个生物重复。解析预期：均值80、合法背景100应为−20；背景未取得时不能输出−20或0，只能输出缺失状态。

故事C：核计数中的团块、漏检和全细胞边界§

人员导入核标记图，软件自动提供核总数、编号图、排除和未解团块数。人员在密集视野打开接管，在确有两核的团块放两个marker，看到分割边界和前后数量差；补一个漏核时可先点定位，只有补齐边界后才加入对象强度测量。新对象表记录原父ID和新增来源，撤销会恢复此前分割但保留修订历史。

若批次有已支持膜/胞质通道，独立细胞模板才输出cell_count；仅核图则成果写nucleus_count。明确多核细胞的场景不强行走单核模板，可以保留核成果并指出细胞计数未支持。用户不需要了解分水岭数学，但能从总数追到每个计入/排除对象。

拒收：原视野没有有效像素却输出0；两个marker示例成功就宣布所有接触核准确；无膜通道仍输出“细胞数=核数”；未标注对象一律当自动误检；人工合并后旧标签ID无映射而对象强度串行；同一对象的多张裁剪被分进开发和留出集。解析预期：独立已确认标签中一个细胞含两个核，统计必须分别为1 cell和2 nuclei；这不证明当前自动算法能识别多核细胞。

这三个故事是依据真实实验工作形态设计的验收脚本，不是已观察客户案例或实测成绩。正常/异常数据包、性能环境、错误放行阈值和方法容差须提前登记；用户操作验收与科学负责人/独立评测承担的量值验收分开。

方法版本和模块版本分开：本章...@1表示公式/算法方法v1，同名非WB执行模块以module_version=1.0.0登记并显式绑定该方法；WB采用下一表与接口章一致的模块名。静态模块描述同时保存module_id/module_version、method_id/method_version与绑定源码/依赖/模型的implementation_digest，不能由字符串同名推定准入。

各结果行统一有sample_id、biological_unit_id、acquisition_id、run_id、method_id/version、input_scientific_asset_ids、status、qc_flags及来源引用；图像结果另带analysis_asset_id、适用时带roi_or_object_id，表格场景不伪造图像/ROI身份。数值字段另带单位。failed/unknown/excluded/not_detected不填有效0。对象属于视野，视野属于实验样本，技术重复属于生物重复；统计的n按方法声明，不能默认把像素、对象、孔或视野都当独立生物学样本。

WB完整成果表至少包含原量值、目标/参照ID、归一化公式、单位、有效/排除/未知状态和样本层级；不能只给一列最终比值。总蛋白归一化、多通道、分子量估计是不同扩展：前者要定义测量区及线性范围；多通道要验证配准和通道采集；分子量需要已知Marker及迁移拟合，只是估计，不能证实抗体特异性。OCR的“45 kDa”也不自动成为分子量校准点。

8. 导出→强度表、ROI/背景证据、分组图 if.report.bundle输出区域与视野表、叠加图、完整状态和方法；图上伪彩/显示窗另存 复用渲染、导出、来源跳转。用于报告的通道颜色不影响量值；组图标题须明确mean/integrated、单位、n

这种流程需要让用户看到区域是怎样来的：点强度表中的一行，画布同时显示结构ROI、目标原强度、背景区与质量异常。面积、强度和计数分开交付。比如ROI4个像素为110/130/150/170、背景100，则校正均值40、像素和160；这是解析预期，不是某数据集的实测结果。若删除一个ROI只为“变异太大”，系统保留原值和理由，不能把删除历史抹去。上游检测可以在副本上平滑；显示、检测和测量数组的来源分别可查。

背景方式从局部环带改为固定背景区，是方法/参数变更，重算受到该背景影响的所有ROI及其汇总。选择多个相交ROI时要明确输出“逐ROI表”还是“ROI并集”；并集以像素集合去重，不能把重叠像素算两次后仍叫总面积。用户画出的自由曲线在测量前成为版本化几何/标签，画笔和截图不会覆盖原图。

输入与候选v1§

先支持二维单通道TIFF或明确CYX的多通道TIFF/OME-TIFF及样本CSV；后者必须核验轴序、通道和像素尺度，未知轴不猜。v1支持已定义区域或结构通道定位的区域强度，默认不将Z轴投影、不做跨曝光自动比较。层级为实验样本→视野→ROI；ROI联合区域与单对象强度分别声明。目标强度通道不直接用于挑出“更亮区域”后再证明整体增强。

拟包tools/if_intensity/src/if_intensity_tool/，链为if.import.channels@1 → if.correct.dark_flat@1 → if.roi.structure_otsu@1 → if.background.annulus@1 → if.measure.region_intensity@1 → if.report.bundle@1。对应领域文件为illumination.py、region_detection.py、background.py、intensity.py，用例为application/run_if_intensity.py。最终导出区域表、背景/质量表、目标通道加ROI叠加图、按样本汇总图和来源记录。

  1. 校正选择。 模板声明有匹配dark/flat时，计算D=I-dark，F=(flat-dark_flat)/median(flat-dark_flat)，J=D/F；分母只在已知有效区域内，零/负或不符合校准条件的F无效。无flat时采用明确的none校正模板，不从实验组的生物分布猜照明场。保留负的背景校正结果和警示，不截成0美化；不按每图最大值重新缩放。照明校正与后续背景扣除是两个不同步骤。[N03]
  2. 自动ROI。 默认使用独立结构通道：在有效像素上做Otsu二类阈值，亮前景取I>T，8连通区域，按冻结面积规则移除碎屑。float阈值直方图bin配置和取样范围写入方法；Otsu仅提供分割候选，不能保证任何图都存在对象。[N01] 不清晰结构转为待处理；已验证固定视野区域模板可作为独立替代方法，不自动切为“全图=细胞”。
  3. 背景。 对ROI外扩形成环带，排除全部结构前景、无效区域和质量异常；以环带中位数B估计局部背景。环带内/外半径、最小可用背景面积从物理对象大小及开发集确定，必须证明环带确实代表背景。背景不足仅在模板已批准时使用预定义背景区，否则输出background_unavailable。
  4. 测量。 在未做检测平滑的J上，mean_raw=sum(J_R)/N，mean_corrected=mean_raw-B，integrated_corrected=sum(J_R)-N*B。ROI平均强度单位a.u.，像素求和记a.u.*pixel_count；物理面积为N*sx*sy[µm²]，不能把积分强度直接标µm²。记录所有原值、B、N及两种端点。不得把WB梯形剖面积分当本方法。

核计数v1与细胞扩展§

核计数输入是二维核标记通道、尺度与视野/样本关系；全细胞计数还需能定义细胞边界的独立胞质/膜通道及该方法的适用细胞类型。没有这些条件，只能报告核数，不能把核外扩固定半径叫细胞。

拟包tools/if_count/src/if_count_tool/，模块为count.nuclei.otsu_watershed@1、count.cells.seeded_watershed@1、count.objects.qc@1、count.report.bundle@1；文件为domain/nuclei.py、cells.py、object_quality.py和application/run_count.py。对象掩膜通过公开端口交给IF测量，两个工具不导入彼此内部代码。

核v1算法：校正检测通道 → Otsu前景 → 按模板去小区域/补小孔 → 欧氏距离变换 → 局部极大值marker → 对负距离做标记控制分水岭。距离按sx/sy计算；无尺度的模板显式使用像素半径。固定marker平局顺序，避免同图不同运行随意改变对象数。分水岭依赖marker；库示例证明算法可实现，不证明它能可靠拆开所有真实核。[N02]

min_area/max_area、最小marker间距、孔洞面积和边缘规则通过开发集对象尺寸/争议标注选择后冻结。v1默认不加入未验证去噪；若测试需要高斯检测平滑，sigma及其物理单位另记入方法，测量仍取未平滑分析图。fallback只允许已验证的“稀疏不接触对象→连通域计数”模板分支；密集、无法分开的团块标cluster_unresolved，不逐个臆造数量。

细胞候选使用已验证核marker、胞质前景及边界梯度上的受限分水岭，输出核→细胞关联；首切片限定已有证据支持的单核细胞类型，不能承诺该算法自动把多核细胞恢复为一个细胞。多核、无核或弱边界超范围时待处理；未来支持多核须增加独立边界/合并方法及证据。关联与统计模块可接入独立已确认的细胞标签，允许一个细胞关联多个核；该能力不等于自动分割已解决多核问题。各对象保存object_id、标签mask、质心、面积、bbox、边缘接触、形状质量、计入/排除原因；ID对固定资产稳定，修订后用parent_object_ids[]映射，不承诺跨分裂合并保持同一生物对象。

方法公式、模块路径与解析验收§

输入先支持板读仪CSV/XLSX，包含原始OD、读数通道/波长、孔位、标准浓度与单位、blank/QC/unknown角色、技术重复及稀释倍数。一个分析批次绑定试剂盒/SOP和板身份。拟包tools/elisa/src/elisa_tool/；elisa.import.plate@1、elisa.preprocess.blank@1、elisa.calibration.4pl@1、elisa.concentration.inverse@1、elisa.report.bundle@1对应domain/plate_qc.py、calibration.py、inverse.py及application/run_elisa.py。

首个候选限定单调上升夹心法4PL；竞争法下降曲线、需要5PL的不对称方法另立版本。空白和双波长扣除只按保存SOP做一次，不能对仪器已校正OD再次扣除。采用如下明确参数化：

y(x) = a + (d-a) * x^b / (c^b + x^b), x >= 0
a=下渐近值; d=上渐近值; c>0=半响应浓度; b>0=斜率参数
x(y) = c * ((y-a)/(d-y))^(1/b), a < y < d

数值实现候选为SciPy least_squares(method='trf')，残差sqrt(w_i)*(pred_i-observed_i)。为落实d>a、b/c>0，优化(a, log_gap, log_c, log_b)并恢复d=a+exp(log_gap), c=exp(log_c), b=exp(log_b)；每个优化变量采用冻结的有限数值边界以防溢出，不将d>a误写成求解器原生支持的任意耦合不等式。用固定多初值（a/d由标准低/高信号初始化，c由正标准浓度中位数，b从预设小集合起步）避免依赖单次初值。保留各次收敛、残差和参数边界命中，限制迭代/时间。[N07] 同一板不能自动在4PL/5PL/直线之间挑最有利结果；模型和权重由开发验证确定后写SOP。

权重候选支持等权与预先拟合的方差模型w=1/variance_predicted；不能把某标准两个相同重复的样本方差0当无限权重。等权仅作为研发基线或已有方差证据支持的正式方法。正式范围需独立QC及回算/精密度证据；模型选择不能只看R²。[N06] 标准点数及浓度分布必须足以识别参数，不能因为“4个参数有4个点”就宣告可靠。

浓度只能在已批准的量化范围内给有效数值；a<y<d只是可求逆的数学域，不等于LLOQ至ULOQ。超范围给状态和必要重测建议，不外推、不设0。先按SOP逐孔反算再处理技术重复，保留稀释前浓度；原样浓度c_original=c_well*dilution_factor，因子必须是显式正数，单位显式换算。

最终输出标准曲线图、每标准观测/预测/回算/回收率、独立QC表、逐孔浓度和状态、样本汇总、板位图及方法包。字段包括standard_x[ng/mL等]、od_raw[absorbance]、od_used、a,d[absorbance]、c[concentration]、b[1]、concentration_well、dilution_factor[1]、concentration_original、quantification_status；空白x=0的百分回收无定义，不能除0。

下载、入库、标注与划分的实现设计§

拟新增开发工具devtools/datasets/registry.py和fetch.py（当前未实现），命令行只消费审阅过的登记记录。每次任务明确dataset_id、版本/快照、目标文件白名单、最大下载量、用途和许可状态，不能收到一个URL就递归抓全库。数据在.local/datasets/<dataset_id>/<version>/{raw,labels,metadata}按内容摘要存放，原文件不可覆盖；公共数据也不直接塞进产品安装包。CI保留独立合成小fixture与必要的有明确分发权的小样本；网络下载测试与离线产品门禁分开。

下载执行应验证HTTPS终点/重定向、长度上限、SHA-256或出版方校验和，记录失败与重试；ZIP入库先拒绝绝对路径、..穿越、符号链接、过多成员、解压体积/压缩比异常，之后再受控解码。按格式保存axes、通道、dtype、原值范围、时间、物理单位、instrument信息和缺失状态；不为适配UI预先转换为8位RGB。元数据缺失时只承认已知单位，不凭图像推测微米或样本分组。

建立DatasetManifest、AnnotationManifest和SplitManifest三个开发证据文件：第一份记来源/许可/摘要/格式/用途；第二份记标注对象定义、标注者、工具/版本、全标或稀疏标注、复核/裁决和忽略区；第三份记固定train/dev/holdout ID及防泄漏分组键。它们是研发数据管理契约，不强塞进每个用户实验项目。任何自动标签只能标pseudo_label；不能与独立人工ground_truth混用，也不能拿算法自身输出作为最终准确率标准。

划分单位最低随实验定义：WB按实验和物理膜；IF/计数按生物样本且同孔/视野全部通道、裁剪、焦面归同组；克隆按原孔/板及实验；划痕按完整伤口时间序列；qPCR/ELISA按原实验/生物样本/板批次；IHC按患者或组织来源；流式按供者和采集批次。同一记录的新旧版本不是独立集；BBBC039来自BBBC022时也必须做跨记录去重。只有单批输入就明确“没有跨批留出”，不能随机分图片后宣称泛化。

9. 模块体系、需求覆盖与特殊实验扩展§

9.1 用有限模块覆盖变化：能力体系§

本章新增体系是4.0目标；后附复用矩阵和方法说明延续3.0科学边界。一个Python包可以包含多个模块；一个节点是某模块版本的一次实例；一个模板是多个节点构成的完整方法。包数量、节点数量和实验数量都不是覆盖率。

9.2 怎样判断模块满足用户需求§

需求登记以“真实任务”而非软件按钮为单位：输入样例/格式、实验端点、希望得到的表图、当前人工步骤、可接受偏差、适用条件、异常样例、执行频次和数据使用范围。先用代表性任务簇构建覆盖矩阵：每一步对应已有模块、可配置差异、待新增模块或方法未知；拿不到样本或端点定义时明确缺口。

9.3 特殊实验扩展：不等待AI，也不任意加载脚本§

每个模块都要附带这一组可执行说明§

模块开发说明不是“实现自动分割”一句话。每个进入开发的模块应在自己的模块目录或方法卡中完整登记以下内容；这些字段与第3章ModuleSpec/资产契约一致，不再发明另一套执行协议。

  1. 端点与输入域： 测什么、适用什么仪器/图像/实验、禁止什么情况；原值范围、通道、维度、单位、坐标系、批次关联必填，不把默认值当测量事实。
  2. 端口： input/output名称、资产类型、schema版本、单位/shape约束、必需或可选、失败是否产生带status的结果。几何必须绑定analysis_asset_id+frame；typed表有主键和外键。
  3. 方法： 公式/候选算法、参数类型/范围/默认值来源、随机种子与实现摘要、软件依赖和模型许可；检测用图与测量用图的具体分界；默认值未验证先标candidate。
  4. 交互： 自动结果如何显示、哪些参数可以编辑、动作目录、作用对象/批次范围、错误定位、是否可快速预览、可撤销语义、依赖失效端口；无编辑需要也必须明确只读。
  5. 运行： 生命周期与进度单位、预览类型、最大消息/内存预算、取消安全点、是否仅节点边界暂停、断点恢复能力。第三方算子不可中断时必须明确显示等待安全点。
  6. 验收： 独立解析例、真实公共输入、人工参考/已知算法参考及许可、留出单位、错误/缺失/超域反例、原始输入不变与恢复重开。依据开发集及独立参考制定指标和容差，在独立留出评测前冻结；准确率是实测输出，不能先看留出成绩再改门槛或由实现算出的数字回填期望。
  7. 兼容： 与旧method/schema不同处、迁移/重算方式、历史结果可否只读、输出依赖摘要。新代码只要可能改变数值或对象身份就不能沿用旧准入摘要。

模块接线在执行前检验类型、单位、坐标、样本身份、method适用域、implementation_digest与准入状态。例如实例分割的label输出可以接IF对象强度，但必须与测量图共frame并有显式通道配准；qPCR的Cq表不能接ELISA浓度反算。连接失败在工作流预检中报告具体端口及修复路径，不等到任务跑完才给“错误”。

把工作流完整性变成成果检查§

每种模板附required_outputs与覆盖规则：样本表、数值表、证据图/曲线、异常表、方法与参数、可恢复项目。结果清单记录预期样本数、有效/待处理/排除/失败数以及每项状态；没有足够参照时可交付诊断成果，但不能称定量成功。模板先作输入预检，再生成固定DAG；所有改变样本集或依赖的编辑通过新revision重规划。

共享导出层只处理类型化数据。CSV数值字段保留精度和明确缺失状态，中文列名/UTF-8/BOM策略按兼容用例验证；XLSX导出时字符串作为字符串，不能把样本名称当公式执行。PNG/TIFF图版由可追溯的视图规格产生，标注数值不因屏幕主题或小数位而改写源表。一次导出先在新目录staging完成，全部必须文件校验通过才发布manifest；失败保留诊断、不给完整成果标记。

10. Agent 什么时候加入，具体做哪些开发§

10.1 先让系统可调用，再让模型决定如何调用§

按第12章M路线推进：M0保留现有可调用模块，M1保存真实图与运行，M2/M3取得人工编排和跨场景复用证据后，M6接入受限AI。影子规划可提前研究，正式执行只使用获准模板/模块；跨实验声明须有相应连接验证。专用模块SDK在M4交付，不依赖Agent；算法研发Agent仍属更后面的独立能力。旧V6/V7分别是两类AI能力标签，不是特殊实验扩展的前置。

Agent 不是另起一套工作流系统，也不通过模拟鼠标去点自己的软件。它调用普通界面使用的应用服务，计划最终落到相同的 WorkflowSpec、资产和任务引擎。模型服务暂时不可用时，实验人员仍能通过已有模板完成工作。

10.4 一条真实任务的执行逻辑§

用户输入“把这批 WB 做成灰度表、内参归一化和拼图”。系统先读取当前批次选择及样本表。若方法、内参和对照已在模板中，Agent 选模板、绑定输入、校验后直接执行；不额外让用户审批每一步。若缺配对关系，只问“哪些样本对应哪个内参/对照”，不能让模型猜完继续。未授权花费、对外发送或新数据上传仍由具体授权边界处理。

  "intent_version": 1,
  "goal": "wb_quantification_and_figure",
  "dataset_id": "batch_001",
  "document_revision": 12,
  "template_id": "wb_auto_v2",
  "outputs": ["raw_measurements", "normalized_table", "figure", "provenance"],
  "execution_mode": "formal",
  "constraints": {"data_egress": "metadata_only", "allow_unapproved_methods": false},
  "missing_fields": [],
  "validation_required": true
}

这只是意图示例；真实执行使用校验后固定的计划 ID，不接受助手自由文本中的文件路径作为运行命令。科研工具请求超时重试沿用 operation/idempotency key；若服务端已开始，返回原 run，不再开一份计算。模型在运行中断线后，引擎按已冻结计划继续；重连先读取真实状态，再解释，不凭聊天历史推断成功。

模型调用费用另设账本，不能靠科研任务幂等保证供应商不重复计费。请求前按配置的最大输出 token、输入估计和价格快照预留额度，限制重试次数与累计预留；超时且计费状态未知的请求继续占用额度，取得用量记录后对账。预算不足停止新的模型请求并保留本地任务。价格未知或服务商不能支持必要限额时，不开启自动付费执行；这些是实现时的真实配置条件，不在本方案里虚构单价。

10.5 受限 Agent 如何验收§

建立版本化任务集，覆盖已知正常目的、等价自然语言、缺少实验身份、错误端口、方法未准入、预算不足、数据越权、取消、服务断连与重复请求。每个题目有独立的允许计划/必需成果/禁止动作；合理计划可以不止一种，不能只逐字比对一个标准 JSON。

首轮建议至少 40 个任务作为工程冒烟样例：12 个正常/改写目的、8 个缺参、8 个非法连接或方法、6 个权限/预算、6 个中断/重试。样例规模是拟定起点，不能据此宣称广泛可靠。另建未参与提示词调整的评测集，固定模型/提示词/目录版本，报告完成率、无意义追问、错误拒绝、执行工具选择、运行费用与耗时分布。

放行的硬门槛是：未校验计划不得执行；测试集中的越权/未准入调用全部被执行层拦截；相同幂等请求不产生重复任务；成功宣告全部能定位真实已提交文件。自然语言理解正确率的对外承诺在取得代表性任务结果后确定，不能先承诺“理解所有科研需求”。数值正确性属于所调用科学模块的独立验收，不以语言模型评分替代。

10.6 新算法开发是一条独立的研发流水线§

V7 的研究任务先结构化：目标端点、输入范围、现有基线、禁止改动的标签/标准、资源上限、训练/调参/独立验证数据边界。Agent 生成候选源代码与方法声明，在隔离环境构建，跑解析例、开发样本和性能探针，再把候选提交给独立评测。评测结果回到方法中心，不能直接把代码文件复制进正式模块目录。

研发步骤 必须生成的可交付物 晋级条件
定义问题 method-spec.json，例如“在明确倍率范围改善密集核分离”，列支持域与端点 有基线和可计算评价指标；“更智能”不构成目标
构建候选 固定源码摘要、依赖锁、模型来源/版本、输入输出 schema、资源需求 可在干净隔离环境重建；依赖与模型使用范围可追溯
开发评测 解析例结果、开发集比较、失败样本和速度/内存 不弱化测试、不删除难例、不只报均值掩盖失败域
独立验证 冻结候选在隔离留出集上的逐例结果与结论 阈值在看结果前定义；科学负责人确认适用域与限制
工程准入 安装/接口/资源/取消/故障恢复检查；包摘要 不破坏宿主，支持声明的接口和环境
发布方法版本 宿主维护的准入记录，关联精确包摘要/证据 独立科学和工程条件均满足；候选生成者不可自签
撤销/回退 禁止新正式调用，历史成果带方法状态说明 历史不可覆盖；重分析生成新结果并说明变化

科学负责人不是要求普通实验人员每次运行都审批算法。正式方法完成一次版本级验证后可以自动用于其适用范围；改变方法语义、模型或关键预处理时重新评估对应版本。没有负责人或代表样本时，可以继续工程框架和研发模式，不能把未知项当已批准科学方法。

在 Windows 本地首个候选实现应选择真正隔离的虚拟环境边界，例如独立虚拟机内运行、输入只读传入、输出经校验接收、默认断网、无生产工作区挂载和凭据。具体虚拟化产品/镜像/可用平台在 V7 技术探针决定，不能把 Python venv、普通子进程或内存预算当安全沙箱。Linux 服务器的隔离方案也必须验证文件、网络、进程和资源边界，而非仅画出容器图标。

独立留出集由评测服务保管；候选不能读取答案文件，研发 Agent 不能无限查询同一留出集然后据此调参。失败后返回预先约定的诊断粒度，重复迭代消耗的留出资格要记录；确认被用于调参的样本转为开发集，并补充新的独立样本。结果需同时包含性能、误差、失败覆盖和适用域，不只挑最优例图。

11.2 企业级首先是可维护和可恢复§

M0/M1持续交付固定依赖、日志关联、失败恢复和版本兼容；M3提前验证第二场景，M5完成对应目标环境交付；多人需求出现时增加身份、项目权限与冲突管理。暂不引入微服务集群、跨机构租户或复杂计费系统。它们各有明确触发条件，不能挤占首个实验成果闭环。

正式发行包必须能够说明：应用/方法/模型版本、支持格式与设备、数据目录、备份恢复方式、已知限制、安装/升级/回退结果。依赖升级独立修改，数值变化与纯重构分开。日志记录 run/node/attempt/revision 和错误码，默认不记录原图和身份敏感内容；用户可导出脱敏诊断包。

资源规划采用实际计量：每批输入字节、峰值内存、CPU/GPU 时间、预览传输、模型调用量、存储和支持工时。将计量数据留在成本表，再决定定价和云端预算。本文不凭当前没有的客户规模或模型价格计算虚假利润。

12. 平台优先的具体实施路线§

本版以M0–M6表示新里程碑，按能力依赖推进，不承诺日历工期。旧V0–V7保留含义：V0独立WB调用、V1校正分析资产、V2可观察自动执行、V3正式WB交付、V4 IF、V5计数复用、V6执行Agent、V7研发Agent。它们不再是全平台串行前置。M编号是规划里程碑，不是新建的任务卡或已获得全部实施授权。

12.1 两条协作线路与明确依赖§

平台线：M0既有模块闭环 → M1通用执行与数据契约 → M2可视编排；M3第二场景从M1后启动，M4专用扩展也可在M1后并行；M5综合交付依赖M2/M3/M4。M6 AI执行依赖M5，研发Agent再加真实隔离与独立评测条件。

方法线：WB新自动校正、IF/核对象方法、qPCR/ELISA等分别做数据、公式、QC和科学准入；用同一平台执行，但各自晋级。WB V3正式交付仍需V1校正链、可靠执行、方法及目标环境证据，不能因平台MVP完成而跳过。某方法缺科学参考时仅限制该方法正式使用，平台可用有明确标签的工程样例继续验证恢复、编排和扩展。

12.2 M0：收拢已有独立WB调用，不重做已完成部分§

输入与现状： P-001已完成基线接入，P-002已有模块信封、旧方法适配、真实worker/结果提交和CLI/GUI对照入口，任务仍in_progress。先核对实际HEAD与任务卡落差，完成当前范围的准确提交独审、所需门禁和集成，不把源码存在等同阶段完成。

复用位置： tool_contracts.api最小协议；wb_tool的application/module_execution.py和adapters/module_execution.py；宿主module_session.py、module_results.py、module_cli.py及工作台对照入口。旧定量语义保持，用户获得同一冻结输入的旧路径/独立路径真实差异及可打开的成果。

退出证据： 独立安装调用、真实PID/退出/结果提交、正常与失败输入、取消和历史恢复、旧方法等价证据；绑定最终提交独审与当前阶段要求。此阶段不以新旋转、自由图编辑器或IF作为P-002的追加条件。

12.3 M1：把单模块运行提升为真实工作流§

前置： M0可信执行基础；以P-003方法验证框架作设计配套，科学资产只取图执行需要的最小契约，不要求所有新算法已准入。既有P-004同时覆盖校正分析方法，不应把它整张卡改成平台前置；接续时拆出窄的科学资产契约任务，保留原依赖，重新登记再实施。P-005从其真实任务范围衔接执行器。

具体修改： 在tool_contracts版本化扩展端口、ScientificAsset与WorkflowDefinition/ExecutionPlan；platform_runtime增加通用图预检、串行调度、依赖失效及CAS账本；宿主以固定模块注册与RunSession装配，沿用真实进程和成果提交，不在runtime导入WB。现有v1输入/输出上限和事件协议保持兼容，新流式/语义版本另行握手。

最小可运行图： 原图/样本输入绑定 → 格式与身份预检 → 成熟WB粗分析 → 带状态的表/曲线成果发布。至少拆出一个真实可复用的输入校验或结果发布节点，不只是把WB窗口画成一框。第一版通过固定JSON模板/程序化图运行；运行仍产出实际文件，不能用mock证明引擎完成。

验收： 合法图可保存/重开/运行，环/缺端口/显示图定量/版本不匹配被拒；破坏结果摘要后不复用；结果已提交而账本未关联时能重启对账；失败独立样本不变零，不覆盖原图或旧结果。先串行和有限批量展开，通用条件/集合控制另交可验收增量。

12.4 M2：实验人员能真正编排、保存和复用§

前置： M1真实定义与执行；可在其契约稳定后并行做控件，最终必须接同一执行器。P-006沿用性能与交互基线，新节点视图另立窄任务，不改变旧任务完成标准。

具体修改： 宿主增加工作流目录/命令/投影适配，web_ui增加节点画布、步骤列表、schema参数表单和运行映射；沿用既有主题与来源预览。先用有限节点集合验证交互，再根据键盘操作、大图和维护成本决定画布库，固定版本独立评估，不因ComfyUI外观直接更换框架。

实际交付： 从模板创建流程 → 替换允许的节点/参数 → 保存实验室模板 → 导入第二批数据 → 一次启动自动出表图。运行中看中间成果，安全边界暂停/取消；模板暴露少量参数，专家可展开内部图。

验收： 用户新增/连接/删除/替换节点的修改在重开后保持，坏连接有原因；移动节点不重算，改分析参数只使依赖链过期，改样式只重新导出；后台事件不夺焦点，旧任务不覆盖新修订。只有预设图展示或节点动画而无真实执行拒收。

12.5 M3：提前用第二目标验证复用§

前置： M1资产与执行契约，明确场景输入和参考数据；不等待WB全部科学准入。首选二维核计数＋IF核区域强度的小范围组合，以第7/8章数据可得性和端点定义核实后冻结范围；全细胞测量不能用核区域代替。如果所需标注暂缺，先做明确候选的工程连接，不宣称科学通过，也不静默换端点。

具体修改： 新实验包提供分割/对象QC/计数或强度测量及模板；宿主只新增受控注册与声明式面板。相同读取/测量/发布能力有两个真实消费者后，才抽到公共实现，补import-linter和独立wheel；禁止工具互相导入内部代码。

验收： 两条不同目标流程实际复用同一对象或至少两个适用的技术节点；相同对象身份可追溯，错坐标/通道/单位拒绝；两工具都能完整出成果，新场景不改runtime实验分支。真实科学准确性按各方法独立记录。第二实验不是给旧WB改名字，也不要求先实现所有IF选项。

12.6 M4：交付第一个特殊实验扩展§

前置： M1稳定契约和可重建worker适配；与M2/M3并行，完全不依赖AI。选一个已有明确定义和参考结果的项目专用方法，先用受信Python包而非引入新外部软件栈。

具体修改： 形成最小扩展示例包、manifest校验、受控安装注册、schema控件和契约测试工具；锁定依赖/实现摘要。生命周期按第9章，从私有候选到限定正式目录。外部CLI支持作为后续适配任务，不在本阶段承诺任意ImageJ/Adobe插件兼容。

验收： 开发者只增专用包、固定注册及自身模板，复用已有批处理/表图/恢复，不修改runtime核心；错误schema、超限、异常退出、路径越界和缺结果被拒。卸载/撤销后旧工作流明确缺模块，已保存结果仍可读，缓存不能绕过撤销。方法未知的扩展保持研究候选。

12.7 M5：平台MVP与实验正式交付分别验收§

前置： M2/M3/M4工程能力，至少相应正式模板的独立方法验证、目标环境与用户体验证据。工程预览可先交，不冒称正式科学产品。

平台MVP应包含：可检索模块目录；能编辑/保存的工作流；至少两条不同目标的完整模板；一种参数或算法变体；一个不修改runtime的专用扩展；批次无人运行、异常清单、重开恢复和来源追踪。这个规模用于证明架构，不代表覆盖全部实验室需求。

演示必须用正常、缺失元信息、超域、坏文件、中断恢复五类批次，既能从模板运行也能编辑一条流程后运行。交付软件入口、授权样例、5–10分钟中文操作单、实际成果、方法范围、已知限制和诊断包。用户验收由用户记录，不能由AI代签；科学与目标环境未通过时标工程候选。

WB方法线保留自动旋转、同源分析资产、条带定位、配对归一化与完整图表包要求。克隆/划痕使用已验证mask/时间身份能力；qPCR/ELISA可在表格契约就绪后独立开展；IHC/流式按大图、门控、数据与方法边界后置。每条是模块加模板的完整交付，不建设互不相通的独立应用。

12.8 M6及以后：AI与方法研发§

先让AI基于真实目录给出影子计划，再经同一编译器与权限/预算校验接入运行；已有模板在模型离线时仍能自动执行。基线验收沿用第10章：未准入/越权计划被执行层拒绝，成果链接只能来自已提交运行。

算法研发Agent是更后的独立项目：定义问题、固定数据边界、隔离构建、比较方法、独立验证、准入或拒绝。M4人工开发的特殊模块已经能承接长尾需求，不能把所有特殊分析都推迟到AI会研发之后。
