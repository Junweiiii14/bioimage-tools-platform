## 发布输入

明确 tag/head、干净源码、锁定 Python/依赖/编译器、通过的检查、绑定 head 的独立审查、已声明兼容范围。按任务提交版本/发布说明，不从未提交工作目录构建。

当前采用已验证的私有CPython与锁定四wheel目录包，加原生固定启动器和Inno安装器。`python -m tooling.build_runtime_candidate --iscc <已核验编译器> --gcc <已核验编译器> --grouped-intake-test` 构建独立采集组候选；`--execution-test`及无旗标的旧发行保留且互斥。记录实际编译器版本和来源，不能将工具存在视作包态通过。早期Nuitka AOT未通过安装启动/OCR，不能代替当前配方。

## 必需验证

- 无开发 Python 的 Windows 干净机：启动、加载合成样本、ROI、计算、取消、重开、导出。
- 中文用户名/路径、只读安装目录、125%/150%/200% DPI、断开的外部输入。
- 数值冻结集、历史 schema、失败/中断恢复、资源准入和真实备份恢复。
- 构建与原生库许可/通知检查；按实际分发方式确认所需义务。

manifest 记录：app/build/git/lock 摘要、Python/Qt/编译器、工具及算法版本、schema/协议/工作区支持范围、所有产物 SHA256、验证报告和已知限制。构建时间可变时不宣称字节级可复现，至少验证输入与行为可复现。

新检出重复核验使用 [候选验证与独立 Windows 验收](candidate-acceptance.md)：`tooling.candidate_acceptance` 关联安装器/源码/payload 并保留失败与新报告恢复；PS5.1/7 使用 JSON 请求入口。可弃安装采用 `--laboratory --acceptance-id <安全ID>`，复用现有模板但隔离 AppId、设置、目录和启动器；只有 `/DIR` 的旧 laboratory 包不能用于本轮隔离安装。真实安装/升级/卸载与目标机矩阵仍单独记录，工具通过不等于目标机或科学验收通过。

## 回滚

先保存不可变旧产物和迁移前副本。代码 revert 不能还原数据；新格式不被旧程序支持时使用迁移前副本或只读导出。恢复演练记录迁移后新操作是否丢失，不能隐藏这一代价。

无明确发布请求时只生成候选产物和证据。当前没有自动发布、生产账号、代码签名证书或后台自动更新器。

本轮只交付本地测试候选，不创建正式GitHub Release。干净Win10、物理DPI和独立科学真值/留出按用户决定留待后续，必须在测试说明和manifest中明确未验，不因缺口冻结已授权产品技术栈。新包验证前不回收旧测试安装/产物；用户原图、项目、结果和旧工作树始终保留。
