# Qt 宿主线程归属

选择 QObject worker 移到专用 QThread，QueuedConnection 按发送顺序处理明确命令。
Workspace/SQLite 从创建到关闭均在该线程；GUI 只收不可变值、字节与请求 ID。
来源：[Qt for Python QThread](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)，访问 2026-10-14。
线程 finished 清理 worker，主线程不 wait/terminate；调用方保留端口直到 closed。
真实事件循环中的存储屏障与定时器验证 I/O 阻塞不阻塞 GUI；失败不使队列失效。

## 后台进程阶段

QProcess.started 登记实际 PID 后，经存储确认与 worker hello 两个条件才发送请求。
协议在独立 QObject/QThread 解码，主线程仅分发有界字节，不进行 Pydantic 数值校验。
EOF 与解码线程 finished 都确认后才处理候选；实际终态在存储线程提交。
来源：[Qt QProcess](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QProcess.html)，访问 2026-10-14。
Linux/POSIX CreateNewSession 将 owned group 与宿主区分；Windows 使用
[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 的
KILL_ON_JOB_CLOSE/继承、TerminateJobObject 与活动进程计数，实际强停一个孙进程已测试。
已注册 worker 必须等请求后才创建子进程；当前 WB 入口满足这个前提，不宣称可约束恶意任意程序。

本机发现 started/退出与 Windows job 计数有短暂不同步；正常退出后先短暂轮询确认，
仍存在的后代强停，全部停止才返回候选。不能以 QProcess.finished 单独外推树已退出。
取消 Event 在 GUI 线程设置，存储的最终提交检查决定取消/成功先后；取消不反写已完成历史。
异常/缺结果/启动失败为 interrupted；工具明确 FailureFrame 为 failed。保留真实 OS 退出回执。
