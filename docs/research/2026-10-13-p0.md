# P0 打包与交互验证依据

关联 T-002；访问与实测日期 2026-10-13。原始 V3.0 PDF 第 4/11/15/25/27/28 页定义 P0，不构成扩大业务任务授权。

问题：锁定 PySide6 6.12.0、Python 3.12.14、Nuitka 4.3 能否在本机用独立 EXE 维持异步桌面与后台计算，并给出可追溯便携目录？

依据：[Qt 的 Nuitka 部署文档](https://doc.qt.io/qtforpython-6/deployment/deployment-nuitka.html)、[Nuitka 手册](https://nuitka.net/user-documentation/user-manual.html)、[QProcess 异步信号](https://doc.qt.io/qt-6/qprocess.html)、[Qt 高 DPI 文档](https://doc.qt.io/qt-6/highdpi.html)。采用 standalone 目录便于检查 DLL、Qt platforms 和 Python runtime。onefile 解压与安装器留后续；不额外引入另一 GUI 路线，除非最小实测失败。

本轮不使用 pyside6-deploy 自动改依赖；直接调用锁定 Nuitka，保存命令、源码提交、uv.lock 与逐产物 SHA256。选用已在 F-001 核验的 MinGW 工具链缓存，2 个编译任务限制内存压力。

发现：Windows 中阻塞 `os.read(stdin)` 与 NumPy C 扩展首次加载同时发生时，扩展初始化停在 create_module；向 stdin 写入后解除。最小 faulthandler 实验记录在本地 diagnose.py。本实现用 Win32 ReadFile 控制管道避开 CRT 描述符锁，之后真实 worker 成功、取消和强停测试通过。另发现 uv venv 启动器创建额外子进程；开发态直接启动 base interpreter 加 venv 搜索路径，发布态用同 EXE。

类型边界：SciPy 当前安装包无完整类型标注，本轮用窄 Protocol 适配单个 Gaussian 函数，解析常数图验证；未关闭 strict 或增加全局 ignore。未改公式测试预期，float32 常数结果绝对容差 0.002（约 2 ULP）。

决定尚为候选：本机证据完成后保留干净 Windows 和跨显示器验收；未完整退出 P0 前不冻结产品栈。新版本、编译器、ABI、worker 控制或图像库变化时重跑对应验证。
