# 模块化科研工作流的接口与生态核验

2026-11-02，B-009。问题：有限模块怎样承接差异需求，怎样实现固定自动流程，怎样扩展特殊实验？本轮仅官方资料核验和本地源码只读审计，不安装依赖、不宣称接入任何外部算法软件。

## 决定与备选

保留现有Qt/WebEngine、worker和Workspace，新增小型确定性图执行与科学端口；不因外观相似直接改为ComfyUI分支。专用方法先用受信Python包和静态登记验证扩展，避免同时引入新外部运行栈。现成通用引擎仍是后续可比较选项，但须证明数据语义、Windows打包、恢复和许可成本优于增量方案；此轮未运行比较基准，不宣称自建必然更优。

## 实际核验与待实施最小实验

本次实际只读源码结果见 [基线审计](../../work/evidence/B-009/baseline-audit.md)：最小协议与WB适配已存在，通用图/科学资产/节点编辑器/扩展SDK未见实现。这是现状核验，不是新技术实验。

后续任务必须实际执行：

1. 两条不同目标流程共享技术节点或对象测量实现，记录运行产物和实际共享调用，区分WB剖面积分与区域统计。
2. 连接显示RGB8、错坐标、错单位或轴顺序，验证预检/解码后拒绝；未知信息不放行。
3. 修改图位置、标签、阈值、原图内容或方法版本，检查不同失效范围与缓存键。
4. 专用Python包在不修改runtime前提下注册、批量运行、取消、提交和恢复；方法与工程准入分开。
5. 如后续选择Fiji，固定发行版/插件/版本，核验无人执行、退出码、超时、取消、位深/单位往返与参考结果。未做此实验前不称已接入。

重核触发：选定第三方依赖、升级接口/模型、改变科学语义或尝试分发外部软件；届时锁定版本和许可并记录真实最小实验，不把本轮网页核验当永久保证。
