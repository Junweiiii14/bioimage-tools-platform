# 采集组草稿 v1

T064在既有顶层schema10–14内新增 `IntakeManifest.schema_version=3`，不改变工作区格式、积分公式或显示转换。旧清单v1/v2序列化不包含grouping，原字段/摘要输入保持；旧读取器拒绝v3。旧行式项目保留原编辑入口，不猜测迁移蛋白归属。

## 身份、草稿与执行

`wb_tool.api`公开 `IntakeDraftFigure`、`IntakeAcquisitionGroup`、`IntakeGrouping`、`intake_grouping`、`save_intake_grouping`。

- Fig具有稳定ID、可暂空标签和唯一N（None或1–96整数）。采集组具有稳定group_id、互不重复的来源成员、可空Fig归属/蛋白名/裁剪来源；裁剪源只能选组内一个，可取消。组ID也是派生蛋白行ID，改名/重排不改变身份。
- 初始组建议按安全相对目录和完整采集名生成，包含采集时间/编号，去除三图变体后缀；不同目录/采集名不按蛋白名合并。后缀仅关联来源，不决定信号/白光/合并角色。未知单图独立保留，文件名不修改。
- 草稿包含全部来源，含未归组/未选择图片，纯JSON可保存重开。完整组投影为既有figures/proteins/assignments；读取器校验投影一致，不能篡改执行清单绕过草稿。未完成组不产生伪造尺寸/ROI/数值。
- 确认时所有已归Fig组必须具备蛋白名、裁剪源和有效Fig标签/N；已选源但未归Fig也阻止确认。未选且未归Fig来源保留在池中，不执行。N包含空槽、不含Marker，不意味着跨蛋白样本相同。
- 仅schema10可保存采集组编辑；执行后保留现修订和阶段历史。旧行式项目不能通过这个接口静默转化。明确N/来源变化使候选选择过期。已知参考成品或失败来源不能作为裁剪原图；相同像素用于多蛋白仍要求显式allow_reuse，不能仅传reuse_confirmed绕过。

## 原子保存与显示

保存必须匹配当前digest。模型修改不可变，真正提交仍经过宿主Storage/CAS及generation/session/取消保护；确认不等于裁剪审核。源、N、标签改变撤销清单确认，完整冻结/裁剪/成图/运行/输出沿用既有版本化主链。

桌面 `intake_grouping` 提交全草稿，成功快照必须精确匹配提交才消除对应本地草稿；保存期间的新编辑保留。后台冲突保留本地输入并要求重新核对。原有行式UI仍服务历史数据。

组内图片平等并排；辅助图跟随标注但不进入裁剪或定量。缩略图128边；放大另走所属后台原图解码，2048边显示专用预览，校验来源SHA/尺寸/位深/字节预算，拒绝旧会话/代际回复。大预览不替换原值资产、ROI或缩略图预算，同一预览编码缓存只保留一个。

## 验证口径

核心验证空N草稿往返、保留辅助/未选来源、稳定ID/N几何失效、越组来源拒绝及旧v1/v2 wire shape。桌面验证真实CAS保存/重开和后台大预览、Web精确保存回执/新编辑保留；科学N/来源对照另见T064本地数据证据，不冒充独立盲测。
