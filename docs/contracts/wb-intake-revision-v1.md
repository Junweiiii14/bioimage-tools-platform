# 执行后裁剪修正 v1

T065公开 `revise_completed_intake_crop`，操作语义 `intake_crop_revision@1`。沿用schema12–14与既有原图坐标/固定N算法，不修改积分、检测阈值、文件格式或工作区格式。旧读取器仍能读取结果快照；独立灰度/OCR不受影响。

输入是当前执行摘要、已完成行身份及明确原图半开矩形。只允许没有活动阶段时调用，拒绝过期摘要、未完成行、越界矩形及缺失原裁剪证据。调用是显式重新审核，不将旧自动定位冒充新的科学证据。

保存后该行crop恢复pending并清除当前raw_crop；新范围按原固定N重分割、仍保留槽位身份。所属Fig的compose/measure及项目export恢复pending，撤销执行批准，删除该Fig当前成图引用与当前测量计划。其他行的裁剪、其他Fig的成图/运行保持；同Fig其余行复用已审核裁剪，完整Fig重新提交后才可重新测量。阶段attempt计数保留，下一次真实claim才递增。

宿主通过普通Storage/CAS保存新的不可变修订。旧工作区修订、RunRecord、原值资产和发布目录不修改、不删除；当前项目保留intake_outputs历史索引，其输入摘要不匹配时显示历史快照，不能宣称当前输出完成。旧运行不再作为当前表格的有效结果。

网页拖动已完成行只建立本地草稿；“保存修正并重算本 Fig”明确说明失效范围，提交后真正保存成功的范围回执才清除草稿。失败或冲突保留草稿；忙态、会话切换、摘要与generation保护沿用现有通路。大预览和目标框只用于显示，执行始终从原资产按原坐标读像素。

验证包括两个Fig的独立失效、旧输出与源文件摘要不变、新尝试原值裁剪、真实宿主CAS历史修订/重开与网页显式操作。科学范围选择和独立真值仍需实验人员核对，不由工程测试推出。
