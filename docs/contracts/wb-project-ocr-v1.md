# 项目拼图OCR与多源结果关联 v1

对应wb_figure_project schema v4 / WBProjectOCR，继承v3的定量计划和v2候选。原v1/v2/v3继续读取。一个项目先支持一张独立TIFF拼图；原图定量来源保持每个FigureRow.source，拼图只用于文字识别和校正。

OCR在已有离线worker运行，复用OCRRequest/ResultFrame、锁定引擎/模型/预处理与RunSession退出/提交机制。项目保存OCR源资产、原尺寸、原始recognition、已提交run引用和可编辑行。保存前后须核对完整RunRecord、结果资产大小/SHA、严格JSON、源SHA/尺寸/引擎版本。重开重新读取资产，不以文档里嵌入的识别副本代替已提交结果校验。

建议行保留heading/label token身份及原识别证据，Fig/蛋白名可修改、添加或删除。初始未确认且未绑定，不按重名蛋白自动选图。人工确认关联时保存目标项目row_id、原图SHA、整行ROI和N；每行对应目标固定网格全部泳道，不重新排序或删除空槽。源/ROI/N变化后关联stale，须重新关联；数值标注/基线变化由原定量有效性判定。名称修改撤回名称确认，重新确认后不改变已经测得的原始积分。

OCR关联表与项目原图行表各自保留标签，绑定不偷偷改写项目元信息。已确认且当前绑定的槽自动引用对应已提交定量结果；缺图/过期/未计算/排除/质量复核不填0。未绑定行显示一个空的状态槽，绑定后按目标N完整展开。可导出OCR标签宽表和逐槽来源/状态表，包含OCR源、OCR运行、目标项目行和定量运行，仍使用字面文本与新文件无覆盖发布。

重新识别成功后重建未确认建议及关联；失败/取消保留之前已保存的识别关联，明确显示本次尝试终态，不冒充识别成功。更换拼图建立新OCR状态，旧草稿/运行仍留在不可变历史。generation改变时后到结果只能留历史，不能覆盖编辑。当前预算沿用4MiB协议帧/16MiB项目文档，最多512可编辑行；界面结果分页200泳道，XLSX每表200000单元格。图像显示/OCR缩放不进入定量。
