# 有限批次索引 v1

P008复用P005的WorkflowLedger、RunSession、Workspace/CAS及依赖缓存。父批次仅记录固定样本/计划/子execution_id、控制意图与子账本检查点；不创造第二套资产、PID或计算结果。批次/子文档身份先持久化再派发。父拥有一个存储端口，子执行顺序使用它，只退出自己的准备服务。

首版预算：16个样本、合计64个冻结节点/256条边、1MiB冻结计划、256次子会话派发、128个接受的父控制（非取消最多127，保留取消名额）。父文档沿用16MiB工作区上限，子图与worker仍沿P005各自预算。它们是有限资源契约，不是实测速度或OS硬配额。

输入导入/冻结失败的样本保留明确原因，不构造零值或假运行。独立样本失败后继续其他样本；终态区分全部完成、完成但有问题及整批取消。质量问题不自动通过科学审核。

已确认的输入/缓存完整性失败只阻断该样本：未启动的prepared运行沿旧pid=0/code=None回执记录失败，不伪造进程；无活动attempt的缓存拒绝保留子账本最后检查点和明确原因，子图仍可在新批次中重试。父索引的failed不补造worker终态。持久化结果不确定（如ENOSPC）则整个批次要求恢复，不当作普通样本失败继续写入。

父控制意图CAS成功后确认接受；取消请求同时立即设置子提交的取消标记，避免等待同一存储线程时让正在提交的结果抢先成功。暂停等待当前节点退出/提交，取消等待实际子进程终止及账本确认。已完成的事务保留。重开默认等待明确继续，按持久子身份检查已有子账本；未建则使用原意图创建，已建则走P005恢复，不恢复算法内存。父检查点只从真实持久子账本读取，不把调用方的状态字典当提交证据。

修改参数或绑定下一批输入创建新批次/子执行，按P005计算键和实际资产检查复用旧成果。完成、科学适用性、用户体验和目标机验收分别记录；本契约不宣称批次产品已实现。

模板沿P007的WorkflowDefinition JSON保留真实节点、连接、输出和数值参数；绑定新原图只更新原始资产/坐标源、输入元信息及AnalysisRequest源SHA，旧ROI/极性等参数不猜测、不自动缩放。无兼容输入或模块时明确拒绝；新数据超出旧ROI适用范围仍保留invalid/空值。WB宿主暂要求同一样本的单一原图及一致报告画布，限制由准入说明，不扩展为任意脚本。
