# WB 比例裁剪策略 lane_ratio@1

用户2026-10-16批准宽高比=1.25×n，原图像素不得重采样。本策略仅改变原图坐标矩形；导出原值裁剪、原始定量和源文件保持既有契约。

`AutoWBSettings.crop_policy` 默认 `legacy_fixed_height@1`。旧记录缺少字段时按旧高度60等显式设置解释；只有明确选择 `lane_ratio@1` 才使用新规则。现有schema8的可选设置字段扩展，不自动重裁历史ROI；旧版读取器应拒绝未知设置而非静默改变。积分算法及automatic_wb_proposals@1的边界策略不变，新的裁剪几何策略单独版本化。

自动选框从现有原像素检测得到泳道跨度与行峰，以 ceil(跨度/(1.25*n)) 和条带有效高度加4像素的较大值作为高度；宽度按1.25*n*高度取整（半像素向上）。原图边界仅平移保持尺寸；放不下或无法包含有效条带则保留失败，不裁短或伪装成功。检测弱信号、饱和、数值异常仍保留；几何自动完成不等于有效定量或人工确认。

公共纯函数 `resize_crop_for_lane_count(crop,n,image_width,image_height)` 保持原图高度与中心，宽度按上述规则调整，中心整数取整误差最多0.5像素。越界直接拒绝，不偷偷移动中心或截短；调用者可提示先移动/缩小框。所有参数不接受布尔伪装整数，n为1–96。

`WBJob.crop_policy` 显式传递后台策略；旧ROI重新分析保持原坐标与原策略。`FigureProjectView.set_crop_lane_count(n)` 以一次变更及撤销记录更新n和ROI，防止中间状态触发重算；已有空泳道索引超出新n时拒绝。`rendered_preview` 是当前真实渲染的只读公开结果，含manifest输出位置；编辑或载入项目清空，宿主仍需检查后台generation。

工程验证在T-036任务。用户指定两图可检出3、5泳道，非所有WB图像准确率承诺；私有图不纳入仓库。
