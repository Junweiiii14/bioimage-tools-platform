# Codex 长期开发流程

## 可恢复的任务单元

规划→实施→独立审查→集成，每项任务对应可观察行为。过程通过文件衔接，不开发另一个 AI 工作流平台，也不恢复已归档 agent-workflow/lab-workbench。

开始：读 AGENTS、handoff 当前索引、任务与目标模块文档；确认 base、branch、dirty 状态；实际跑最小基线。继续任务时恢复仓库事实，不依赖聊天摘要猜测。

规则加载执行 `dev.py context --task <ID> --scope <目录> --record` 并读取输出，PR 检查自动拒绝遗漏/过期/超范围回执。没有人在旁提醒也是同一流程；机制边界见 `runbooks/rule-enforcement.md`。调研和非编码产物按 `research-protocol.md` 验收。

实施：按就绪任务最小范围改动。普通命名、拆分和可逆实现选择自行决定；没有充分证据的科学含义或数据删除不得推断为授权。测试规则和用户已有授权优先于安装技能的通用建议，不反复问已经明确的问题。

自验：先相关测试，再反向依赖；共同接口变更扩大范围。复验保存命令、返回码、环境、commit 和关键结果，未跑就写未跑。失败两次且没有新假设时整理诊断，换验证方法而不是叠补丁。

独审：重新读需求和契约，检查指定 base..head，自行复现关键用例并尝试反例。作者说明仅是线索。审查结论含位置、触发、影响和重现，禁止把另一窗口或另一模型自动等同于正确性保证。

集成：检查 head 与证据一致，按 PR 处理并保留回滚。用户未请求发布时只准备可审查变更；持续维护不等于自发启动计划中的产品任务。

## 速度与稳定性

- 根 AGENTS 控制在 8 KiB；参考方案、研究和历史通过链接按需加载。独立子目录的规则在进入修改前显式读取。
- 依赖与 skills 固定版本；本地优先增量检查、CI 做全量，昂贵的打包在构建变化/候选发布执行。
- 配置只把本项目推理强度默认设为 medium；模型选择沿用用户设置。复杂协议、算法或审查可在对应任务提高强度；不全局强制最高强度，不擅自启用付费加速档位。
- 多会话写入时一个任务一个工作树；没有实际并行需要时一个执行者更容易保证接口一致。
- Skills 是可读工作说明，不是已证明可靠的自动修复器。优先官方文档、明确验收和真实工具输出。
