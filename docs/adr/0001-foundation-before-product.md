# ADR 0001：治理基础先落地，产品选型保持待验证

- 日期：2026-10-13
- 状态：接受（仓库治理）；产品技术选型仍为候选
- 背景：初始 V3.0 方案建议先 P0 后完整 P1；用户现明确要求深度调研、规则和环境安装，仍未要求业务实现。

决定：保留原始 PDF 和初始提交；在独立分支建设文档、锁文件、检查、技能和交接。创建空 workspace 根，暂不预建 apps、SDK、WB 或未来 IF/IHC 包。已实现命令只承诺基础设施检查。

选择 Python 3.12.14 保持方案兼容，uv 0.13.0 和直接依赖固定版本，传递依赖由 uv.lock 锁定。Python 3.12 安全维护截止预计 2028-10，P0 比较 3.14/后续受支持版本的 wheel 和部署兼容后再决定产品基线；不会把环境安装成功误当原型验收。

未选：直接生成完整平台、Tauri/Electron 并行技术栈、微服务、多仓库、全局技能集合和常驻代理编排。它们会扩大当前待验证边界，缺少收益证据。

后果：首个产品任务仍需冻结参考样本和执行 Qt/worker/打包试验；本次环境烟测不覆盖 DPI、取消竞态、干净机安装或科学正确性。若 P0 失败，新增替代 ADR，不重写历史决定。

依据：[原方案](../../生物图像工具平台与全AI长期迭代技术方案.pdf)、[Python 生命周期](https://devguide.python.org/versions/)、[uv workspaces](https://docs.astral.sh/uv/concepts/projects/workspaces/)。
