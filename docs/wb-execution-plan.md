## 2. 不变的产品要求

1. 仪器目录→Fig/蛋白/N清单→原名与缩略图分配确认→路径/布局/表格占位→固定N定位与原值裁剪→完整Fig拼图→原像素定量→按身份填CSV/XLSX。
2. N包括空槽，不含Marker；同Fig跨蛋白只共享N，不默认共享样本顺序或像素位置。键使用稳定Fig/行/槽位ID，不使用名称或数组下标替代身份。
3. 无信号、未上样、缺图、检测失败、用户排除、真实测量零值分开。未经有效运行提交，结果为空并保留状态。
4. 异常仅暂停相关行；同Fig缺行保留占位且不触发其定量，其他完整Fig可以继续。摘要确认后运行，不能把部分成功写成整批完成。
5. 新批量链不调用OCR重建已知信息；独立拼图灰度入口继续支持离线OCR、校正、手动测量与导出。
6. 每次输出新目录；原图、完成结果、PDF不覆盖。显示变换、旋转排版、注释像素不进入定量。归一化需要显式样本关系。

- 修改重点：`tools/wb/src/wb_tool/application/instrument_intake.py`、figure_project及持久化适配；新增职责优先落在现有包内。

### E2：宿主阶段调度与异常清单（依赖E1，映射M3/M4基础）

- 修改重点：desktop的AutomaticWorkflow、InstrumentIntakeSession、ProjectMeasurementSession、Web桥接；复用RunSession和AsyncStorage。
- 将“定位后定量”的旧快捷链与新主链隔离，新协调器只推进阶段、处理取消、提交状态；几何/测量放WB用例。
- 阶段状态显式表示待运行、运行中、待复核、失败、取消、完整提交；这是职责建议，具体枚举须对齐既有协议。一次只运行一个计算任务，先不扩并发。
- 增加运行摘要、异常行定位/原因/修正/重试入口；停止后保留已完成行和未处理占位，过期revision消息不可覆盖新草稿。
- 验收：以可控测试执行器验证完整Fig才触发定量；坏行阻塞所属Fig而不阻塞其他Fig；确认后编辑、切换项目、连续取消、关闭/保存失败不会假成功或丢草稿。

### E3：固定N几何与原值裁剪（依赖E1/E2，映射M2）

- 修改重点：WB domain/application automatic、crop_suggestions及原图裁剪适配，复用既有ROI/Marker逻辑与人工修正。
- N由清单显式输入；先建立N个独立槽位，再标信号状态。保存膜/Marker/边界/间距依据、原图坐标、策略版本与复核状态。
- 首尾空、连续空、全空、弱信号、无Marker、不等距、斜膜、多曝光、同图多区域分别建用例；无可靠证据只能出待复核建议，不能均分后冒充成功。
- 同Fig各行独立定位，不能借另一蛋白图推样本顺序。输出原值TIFF与显示裁剪分开，像素身份和来源可追溯。
- 验收：合成已知坐标/像素精确预期；真实留出逐图报告槽位定位误差、漏检、错误自动接受和人工修正率。容差与可接受阈值在调参前冻结；无真值不宣称科学通过。

### E4：按清单拼图后触发原像素定量（依赖E3，映射M3）

- 修改重点：laboratory_layout、figure_export、project_analysis与桌面测量会话。
- 已规划位置按行ID填充，不因缺图向前挤位；标签来自清单，保留分段和手动布局能力。
- 完整Fig达到就绪并持久化后才触发其测量；测量输入解析回原图SHA、原坐标、ROI和参数。显示旋转/对比度/缩放不能替代原数组。
- 在此收敛渲染入口：PNG/TIFF/ZIP与预览尽量复用同一冻结渲染；分格式编码及写后读取核验保留。
- 验收：两个Fig其中一个缺图时另一Fig可完成；同名蛋白/不同槽位顺序不串值；改变显示参数而原ROI不变时定量不变；点击图块可回溯正确来源。

### E5：身份填表、导出与阶段恢复（依赖E4，映射M4）

- 修改重点：project_tables/project_export、automatic_export、project_restore及宿主状态提交；平台只补通用存储缺口。
- 每行/槽位只接收匹配冻结修订的已核验run；成功数值、待算、复核、缺失和失败分别输出；不按最终显示行号填表。
- 输出清单、原值/显示裁剪、Fig图、CSV/XLSX、来源/算法版本、处理状态与可恢复归档；每次新的结果根目录，重名使用稳定ID。
- 在阶段完成点恢复；半成品重新执行而不标已完成，不承诺算法内部断点续算。来源变更或缺失进入异常清单。
- 验收：阶段前后取消、写盘失败/磁盘不足注入、源文件改变、重复导出、重启恢复、旧归档重开再导出；旧结果摘要不变；缺结果不落为0；跨蛋白归一化仅显式映射后可用。

### E6：性能、结构和交互收敛（依赖E5，映射M5）

- 先完成一份真实批次纵向闭环，再按采样热点优化：解码缓存按SHA/平面/策略区分，原值与显示缓存分离，有内存预算和淘汰；不默认改常驻worker。
- 按每个来源/阶段统计解码与渲染次数；不变修订多格式导出目标为共享一次布局渲染，跨进程传递或内存预算不允许时记录例外并测量。
- 将主窗口和视图的已汇合职责继续提取；移除重复编排要先有调用者表和回归证据。独立灰度、OCR、模板、历史读取不可作为“旧代码”直接删除。
- 界面呈现清单→裁剪复核→拼图→结果；状态和下一操作明确；异常可定位；键盘焦点、中文截断、空/忙/失败状态及125/150/200%DPI检查。
- 基准固定硬件/数据/版本，分别记录冷启动、各阶段耗时、峰值RSS、取消延迟、解码次数、产物体积。正式性能比较建议至少20次有效观测报告p50/p95及波动，昂贵批次若不足须注明样本量。
- 优化通过条件：原始像素/来源/科学结果与已冻结预期一致；选定瓶颈改善超过基线波动；其他指标未出现超过预先记录阈值的回退。阈值在E0测量后、改代码前冻结，不事后放宽。

## 5. 连续推进协议

计划阶段负责把范围和验收说清；实施阶段才连续改代码、验证和推进。当前聊天仍是Default执行模式，本轮按用户意图交付规划，没有假称已切换应用Plan模式。用户已选择不设定时任务；本计划不是后台调度器，会话停止不承诺继续执行。

每个工作包按以下闭环执行：

1. 恢复最新handoff与唯一任务状态，核对HEAD/dirty及前置证据；建立具体任务ID，按修改目录执行context并读取输出。
2. 先读目标模块README/API/契约，记录最小行为和独立验收预期，再实现；避免只按文件行数拆分。
3. 运行相关测试和反向依赖检查；接口/生命周期/持久化变更执行完整门禁与隔离wheel，UI变更补真实宿主验证。
4. 产品提交后进行非作者独立审查，修复发现并按新head复验；没有独审时保持review，不标done。
5. 更新任务、证据与handoff，附下一项就绪工作。普通命名、模块拆分和可逆修复自行处理，不逐步索要重复批准。
6. 前置验收通过即进入下一工作包；遇局部科学真值/环境缺口可继续不依赖它的工作，但最终相关验收保持未通过。

同一失败连续两次且无新假设时转诊断，保留原始日志与进程退出码，不无限重试或削弱断言。只在科学语义/真实样本映射需要用户输入、未授权删除/对外通信/发布、目标环境不可获得等实际边界停下相关路径。

当前不额外开启子代理。后续独审使用可用的独立审查渠道；如另有明确授权并行开发，每任务独立worktree和分支，同一树只允许一个写入负责人，Qt集成测试串行。
