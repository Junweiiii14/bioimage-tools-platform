# RULE-001：显式阶段集成的规则回执验证

- 状态：in_progress；T-043分阶段同步的治理前置项，单独PR、测试与独审。
- 问题：现门禁要求PR只变更一份回执，包含多个历史任务的阶段分支被拒绝。不能删除/重命名历史回执，也不能改成“任意一份通过即可”。
- 保持普通单任务路径原行为；仅显式集成清单允许多个历史回执。
- 集成清单指定唯一当前回执、准确PR base、生成时source HEAD，以及每份历史回执的原始提交。集合必须完全覆盖所有额外变更回执，来源必须为祖先、内容不可改变，并校验各历史回执在其来源提交的规则与原基线。
- 当前回执仍校验精确base/HEAD规则、任务存在、完整改动scope；历史清单不能豁免当前校验。
- CLI仅新增显式--integration（配合--record），生成可审查清单，不自动放行多任务PR。
- 负例覆盖：无清单、漏/多列、伪造来源、非祖先、历史内容更改、历史/当前规则漂移、范围遗漏、错误base。
- 不修改服务器ruleset、成功状态、测试容差、skip或锁文件，不合main。
