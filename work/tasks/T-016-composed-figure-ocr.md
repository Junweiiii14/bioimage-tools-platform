# T-016：生成拼图与PNG识别衔接

- 状态：review
- base commit：5cf7c71；分支feat/T-016-composed-figure-ocr。
- 依赖：T-012模板成图、T-014项目OCR/自动写表、T-015归一化；独审另行待办。

## 目标
补上软件已经生成PNG但OCR导入仅支持TIFF的流程缺口。项目支持导入PNG拼图，且当前已审核拼图可作为独立OCR源进入既有识别/人工校正/明确关联/自动填表过程。保存源文件、尺寸、SHA和生成来源记录；原图定量始终使用原始TIFF及已提交测量。

## 实施前检查
核对T-015最新提交，读取根规则、模块地图、OCR预处理/协议/项目契约及figure_export、存储导入与显示实现。按任务scope记录context后修改。PNG解码/透明/色彩/方向/预算须有明确契约与官方来源；不扩展定量TIFF适配器去接受显示副本，不静默变更旧OCR预处理身份或使旧项目结果失效。

## 验收
- 外部PNG导入和程序生成PNG均校验实际格式、尺寸、SHA与来源；损坏/不支持图像明确错误。图像解码/成图/编码/识别在后台，生成来源记录不得作为执行指令。
- 当前拼图转OCR使用完整导出像素而不是缩略预览；确认生成来源与源项目修订，后到结果不能覆盖新编辑。重用既有成功提交/取消/失败/退出机制。
- 原图测量与归一化配置保留；OCR成功后仍给未确认建议并需明确绑定，不根据生成标签或重名蛋白自动假定实验关系。原资产和旧历史不覆盖。
- 包含有解析真值的PNG解码/范围、真实离线OCR进程、Qt导入/生成/识别/保存重开、过期/取消/关闭、旧TIFF兼容与安装后验证；不宣称真实准确率或最终产品通过。

范围拟为tools/wb、apps/desktop、tests、tooling、docs、work、.agent-handoff及uv.lock；若需改变平台或增加依赖先按真实需要更新范围/契约。JPEG、多拼图、批量元信息、统一归档等按首版核对表另行安排，不因此丢弃原任务。
