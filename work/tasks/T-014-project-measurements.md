# T-014：项目级原图定量、OCR关联与自动结果表

- 状态：review
- base commit：5bea9d3；分支feat/T-014-project-measurements。
- 依赖：T-012多源项目、T-013自动建议复核；T-009单源OCR/工作表/定量协议与事务。

## 目标
把多原图项目与已有定量、真实OCR和自动写表串成同一可保存工作流。不能只生成拼图便宣告首版完成。首先实现已审核行→明确原图定量标注/曲线复核→逐源运行与项目结果；再接入拼图OCR行名/Fig与项目行的显式关联/自动填值。重复蛋白、同Fig多源和空泳道仍需稳定身份，禁止按标签或拼图像素坐标猜测测量来源。

## 开始与设计边界
2026-10-14用户补充：CLX来自特殊设备，本软件忽略；其他设备提供TIFF原图，裁剪后为TIF。两种TIFF扩展继续支持，不仅凭扩展或数字后缀推断具体文件的定量身份。保留原图→裁剪的SHA/坐标关系。CLX不再作为阻塞项或开发待办。

新分支先核对git、根规则/交接与适用模块契约，运行context并记录。研究与冻结多源结果schema/有效性规则，再做最小纵向界面闭环。优先复用AnalysisRequest/Result和已有进程/持久化终态，平台不增加WB字段。项目文档按新版本显式读取，旧v1/v2保持；修改ROI、极性、基线或源身份必须使对应结果失效，名称修改不能改变已测灰度。

裁剪只给几何范围，不能自动替代目标band边界和基线复核。按原图加载、逐源运行，空/缺失/未检测/排除/失败不写成0。后台状态显示、取消部分完成、关闭重开、来源损坏、旧修订结果拒绝须有测试。数值显示仅来自已提交且身份一致的结果。界面沿用现有曲线/基线能力，避免新增一套公式。

## 验收方向
至少两个不同SHA、同名蛋白/不同Fig、缺图和空位的真实Qt流程：确认裁剪→调整定量标注→运行→复核→项目汇总→保存/重开→XLSX导出；组合图OCR提议后用户校正Fig/行名并确认来源关联，结果自动填入对应单元格。参数编辑与取消不能泄漏旧有效值。使用合成解析真值和用户样本只读探针，保留原文件SHA。

归一化需要明确参照行、样本对应和异常分母规则；若本任务不能覆盖完整语义，单列后续实施任务并保持首版验收未完成，不能悄悄采用epsilon或默认分母。导出归档整合、批参数/缩略图、元信息导入、模板精修、产品打包和独立审查继续保留在work/wb-acceptance.md。
