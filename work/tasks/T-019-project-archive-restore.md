# T-019：ZIP 归档检查与项目恢复

- 状态：review（作者实现/398全量/隔离安装通过，独立审查待办）
- 依赖：T-018 archive v2，项目 schema v1–v5 与不可变工作区；前序独审仍待办。

## 目标

让用户能把统一 ZIP 作为可携带项目重新打开，查看归档中的原图、裁剪、OCR、定量/归一化结果和来源，并在新的工作区继续编辑与计算。满足总体方案11.4，不能靠丢弃旧结果或伪造本机运行来宣布恢复完成。

## 开始

读根/handoff/module-map、wb-project-archive-v2、项目各schema、Workspace/RunSession/结果核验契约及实际导出实现。先冻结恢复信任与兼容方案，再按实际范围记录context；平台变更确有必要时才扩大scope并读规则，不添加WB语义到通用存储。

## 范围

- 有界后台 ZIP 检查：格式、成员集合/重复/路径、压缩与解压预算、索引SHA/大小、项目来源资产、原始请求/结果身份、OCR副本和派生结果一致性。不能直接extractall；拒绝越界/链接/设备名/加密/未知格式。原ZIP保持不可变。
- 恢复到新工作区/新项目，不覆盖已有资产或项目。事务/分阶段清单、取消/关闭/损坏留下明确状态，不把半导入列为可用项目。支持再启动和结果文件追溯。
- 明确区分外来历史运行证据与本地观察到的PID/退出/成功记录。保留原ZIP和历史原始结果，展示来源身份/验证状态；当前参数与历史不匹配时不给有效当前值。本机重新计算形成真实新run。
- 先设计可审查的外来证据模型/显示/后续保存再编码；如需schema v6，版本化并验证v1–v5继续读。不能把ArchiveRunEvidence当成新的本机提交记录，也不能静默清空旧run后称恢复成功。
- 旧T-012无archive.json的ZIP明确说明兼容范围；未知格式明确拒绝，不猜字段。

## 验收

导出→新工作区恢复→重开→编辑失效→真实重算闭环；原图/裁剪字节、4000/真0/缺失/失败/未确认、OCR原文/显式绑定、归一化和同名蛋白身份都可核对。伪造/缺失/坏摘要、重复路径/解压炸弹、来源变化、旧/未知版本、已有目标、取消/关闭/中断/后到结果均有反例。作者测试与独审区分，完整门禁/隔离安装与证据绑定提交。
