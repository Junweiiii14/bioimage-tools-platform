4. 只读检查命令：`uv run --locked --no-sync python work/programs/scientific-agent-platform/check_plan.py`。它检查文件、ID、状态、依赖环和基本元数据，输出仅由依赖得出的候选任务；不证明科学、实现、权限或验收已通过。
5. 执行任务仍使用真实`dev.py context --task <ID> --scope <目录> --record`和目标树支持的基线参数。此脚本不是新的dev.py子命令，也尚未接入CI必需检查。

## 权威与转移

任务元数据位于任务卡唯一的`PROGRAM_TASK_META`块；status只存这里。正文说明输入、边界和验收。registry只存工作包图与任务路径；W01有D1设计契约与S1具体方法准入两种门槛，P-003的done不代表S1。

`task_execution_root`未激活时为`.`，代表任务卡保存在当前计划树且均尚未实施。P-001接入产品树时，在目标registry设为`.`，源registry在允许修改的源树改为目标绝对路径或可解析的定位地址；禁止修改或已冻结的发布分支仅保留历史快照，由接入PR合入main后统一权威。历史分支/提交中的源任务卡不再更新，视为转移前快照。目标任务成为唯一状态源，有转移指针的源checker转读目标registry/任务；冻结发布分支需从main最新handoff定位，不运行其历史checker推断当前状态。计划迁移PR记录源/目标、摘要和激活提交；换机器时先解析定位，不凭绝对路径猜成功。

registry的task_execution_root定位任务状态权威根，任务元数据execution_root记录该任务实际代码工作树，两者可以不同，以支持并行独立worktree；已完成任务的旧执行路径也可仅作历史记录。检查器只检查路径和commit格式，不认证Git对象、授权或审查真实性，实际验证由任务证据承担。

旧transfer-manifest.json是B-005历史快照，不适用于B-007。P-001先按当前主方案、入口、任务和证据生成/审查新的摘要白名单，再区分直接复制的新设计文件和必须语义合并的治理文件。它不是自动复制脚本，也不包含旧产品、.venv、私有原图或旧规则回执。目标树已有内容不覆盖；激活后重新生成规则回执和检验结果。

## 如何扩展任务

工作包门槛明确后，从task-template.md建立新任务，核对全部活动树及最新可用Git引用中的ID，添加registry路径。每任务一个可观察行为，状态planned→in_progress→in_review→done，外部阻塞用blocked并说明具体范围与可继续工作。没有实际验收的工作包不通过给它补一个done字段来完成。

用户验收直接引用B-007第7/12/13章的场景、版本与验收动作；旧U01–U12仅作补充：给可运行入口、固定样本、步骤、预期成果和限制。工程、科学、用户体验、环境和发布分别记录。未安排用户演示时写未验收，不能代签，也不阻止无关工程继续。

维护者在每个里程碑核对依赖与链接、撤销过期证据、更新版本与handoff。Word是主计划版本快照；任务状态变化通常不需要重出Word，主目标/验收标准改变才更新对应快照。
