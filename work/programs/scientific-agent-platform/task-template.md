# 新任务模板

复制时替换所有占位符，核对ID后再登记。以下是模板，不是已执行任务。

任务标题：ID与可观察行为。

任务元数据使用单行HTML注释PROGRAM_TASK_META，JSON包含id、status、work_package、depends_on、execution_root、owner、base_commit、head_commit。唯一status起始planned；不得复制一个没有真实证据的done。

## 输入与前置

绑定前置任务/契约版本、实际代码树、数据用途/样本摘要、已有证据；区分工程设计就绪与具体方法科学准入。记录授权范围，既有授权不重复索要。

## 用户可见成果

本次给用户什么，怎样启动，哪些主计划U项和场景专项适用；所需用户/方法负责人确认是什么，目前是否真的取得；缺席时能继续哪些工程工作。

## 范围与不变量

允许写入目录、唯一接口负责人、并行排他范围；输入输出类型、单位、坐标、版本、身份、错误/未知/取消语义；不做项和受影响旧行为。

## 最小实施步骤

先真实context与模块阅读，再一个最小行为切片。公开契约只有一个版本源；纯重构与科学变更分开。必要时拆子任务，不靠空目录制造完成。

## 验证和失败条件

独立预期及来源、命令、样本/环境、指标/容差、失败/排除口径、故障与恢复用例；命令必须实际存在。预期/容差/skip/锁/门禁改动单独说明。未知科学标准不得由AI填成通过。

## 兼容与回滚

方法/协议/schema变化、旧读者行为、迁移副本/备份、反例、资产保留、撤销及回退方式。只读不等于能读未知schema。

## 完成证据

命令退出码、环境与base/head、独立审查者及提交、发现关闭、集成/发布边界；工程/科学/用户体验/环境/发布分别列真实状态。实现后未约定集成保持in_review。

## 阻塞与继续

具体阻塞、解除证据、负责人角色、影响范围、可继续的独立任务和当前下一步骤。收尾更新任务及handoff，不复制全部任务状态到snapshot。
